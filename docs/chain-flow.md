# 思维链完整流程 v3（五道确认门：设计稿/素材/原型/契约/每轮验收）

> 供用户审核的产品流程。v2 的问题：设计稿门标注为"可选"、缺原型环节、验收为
> 单轮。v3 修复：**设计稿门强制、新增不写代码的原型环节、代码开发放最后、
> 多轮交互动态验收（逐页优化 + 市面优秀产品替换）**。
> 关联：SKILL.md（agent 指令）、`references/design-contract.md`、
> `references/inspiration-library.md`、`docs/quality-monitor.md`。

## 一、总览

## 二、环节详解

| # | 环节 | 执行者 | 输入 → 输出 | 确认门 | 证据 |
| --- | --- | --- | --- | --- | --- |
| 0 | 需求接收 | 主代理 | 需求 → 任务分类 | — | 计划 |
| 1 | 初步设计稿 | 主代理 | 需求 → 方向稿（基调/结构/动效意图） | **门A 强制** | 方向稿 |
| 2 | 素材检索 | 子代理 A | 方向稿 → 候选清单 | — | research-notes.md |
| 3 | 素材选择 | 用户 + 主代理 | 候选清单 → 选定素材集 | **门B 强制** | 选择记录 |
| 4 | 初步原型（不写代码） | 主代理/子代理 | 选定素材 → 原型图（生图或提示词） | **门C 强制** | 原型图/提示词 |
| 5 | 设计契约 | 子代理 B | 原型方向 → DESIGN.md（含动效规格） | 门D 按需 | DESIGN.md |
| 6 | 代码开发 | 子代理 C | 契约 → 可运行页面 | — | 代码 + 静态核查 |
| 7 | 多轮交互动态验收 | 主代理（命令）+ 用户 | 页面 → 每轮问题清单 + 替换建议 | **门E 每轮强制** | 走查记录/证据 |
| 8 | 交付入库 | 主代理 | 验收通过产物 → 构建/证据/推送 | — | commit + ACCEPTANCE.md |

## 三、五道确认门（用户操作）

1. **门A 设计稿**（环节 1，强制）：主代理出初步设计稿（视觉基调、页面结构
   草案、动效意图，**不写代码**）发用户；用户看不通过就调整重发。
2. **门B 素材选择**（环节 3，强制）：候选素材清单发用户，用户勾选；
   **未选素材不得进入原型与实现**。
3. **门C 原型**（环节 4，强制）：不写代码的原型（生成图或提示词生图）发
   用户；用户看不通过就调整素材/提示词重出。
4. **门D 契约确认**（环节 5，大项目/动效复杂时强制）：DESIGN.md + 动效方案
   发用户确认。
5. **门E 每轮验收**（环节 7，多轮）：每轮走查后把"逐页动效/交互问题 + 可
   替换的市面优秀产品/组件建议"发用户；用户勾选本轮修改项 → 修复 → 再走查；
   **直到用户确认通过**才进入交付。

规则：未过确认门不得进入下一环节；验收记录必须显示每个适用确认门已通过。

## 四、初步原型（环节 4）双路径

原型阶段**禁止写代码、装依赖、启动开发服务器**，两种路径任选或组合：

- **路径 a（agent 生成）**：用用户选定的素材，调用生图能力或 Stitch MCP
  生成原型图给用户看（有则用之，无则降级到路径 b）。
- **路径 b（用户生成）**：agent 输出一份**生图提示词**（描述构图、风格、
  色彩、动效意图，可直接粘贴到 Stitch 网页版等工具），用户生成图片后给
  agent 看，agent 据此微调提示词或进入契约环节。

## 五、多轮交互动态验收（环节 7）

代码完成后不是单轮截图验收，而是**逐页、多轮、对照市面优秀产品**的验收：

- **每轮输出**：真实浏览器走查（键盘全旅程、点击、动效 normal/reduced/中断）
  后，生成**逐页清单**——每个页面列出：当前动效/交互问题 → 优化建议 →
  可替换的市面优秀产品/组件（来源 URL，来自灵感库与画廊）。
- **用户决策**：用户勾选本轮要执行的修改与替换项（也可要求替换为某个
  指定的优秀产品）。
- **执行**：一轮有证据的修复（优先复用市面优秀开源实现，走素材选择与授权
  核查，不主张"自己写的一定最好"）→ 再走查 → 下一轮。
- **终止**：用户确认通过，或明确说停止迭代。

## 六、动效规格与 MCP 调用点

| 动效类型 | 规格 | 实现能力 | MCP/工具调用点 |
| --- | --- | --- | --- |
| 交互反馈 | hover/press ≤150ms、spring 或 ≤150ms 过渡、禁 transition:all | motion/react 或 CSS | Motion MCP `generate-css-easing` |
| 动态流转 | 状态切换空间连续性（shared layout、AnimatePresence、级联 40-80ms） | motion/react | Motion MCP `search-motion-docs` |
| 背景动画 | 克制光影/网格/渐变流动，reduced-motion 降级静态 | CSS 或 motion/react | Motion 文档 + 浏览器证据 |
| 视频/时间轴（仅视频任务） | frame 时钟、确定性时间轴 | Remotion | `remotion-video-agent` + Remotion skills |

**边界**：网页动效走 Motion；Remotion 只用于视频/时间轴，不用于网页交互。

## 七、执行者分工

沿用 SKILL.md「Orchestrate agents」契约：主代理做 0/1/3/4(提示词)/7/8（分类、
设计稿、确认门交互、验收命令、交付）；子代理 A 做 2（检索）、B 做 5（契约）、
C 做 6（实现）。每环节执行者与每个确认门的通过情况必须写进验收记录。

## 八、v2 → v3 修订记录

- 门A 设计稿：由"可选初看"改为**强制**（用户明确要求"设计稿我要看"）
- 新增环节 4 **初步原型**：不写代码，生图双路径（agent 生成 / 用户用提示词
  生成），门C 强制
- 代码开发（环节 6）明确**放最后**，前置于原型与契约之后
- 验收改为**多轮交互动态验收**（环节 7）：逐页问题清单 + 市面优秀产品替换
  建议，门E 每轮强制，直到用户确认
- 原则写入："不要总以自己写的为主，用市面优秀实现优先；多问我、多让我看到"
