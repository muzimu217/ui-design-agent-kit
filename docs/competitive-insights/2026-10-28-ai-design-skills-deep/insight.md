## 机制观察（Part A 写作工艺六点）

1. **批量 intake**："ask only for what is missing, and ask in one batch rather than one question at a time"——与 kit 门 A 方向稿的批量收集同思想。
2. **合理假设显式声明**："If the user cannot answer, make a reasonable assumption, **state it in one line**, and continue. Do not stall the build."——推断值一行声明+不停摆=与 kit image-to-code fidelity brief 的"inferred values 记录"同构。
3. **编号骨架模板**：above fold 5 件/mid page 论证 4 段/bottom 异议处理 3 件——结构化页面模板（与 kit 页面结构 reference 同族）。
4. **布局路由表**：A3 四布局×use when 表格——与 kit tool-routing 的选择表同构。
5. **❌/✅ 正反例对**："❌ Save time and streamline / ✅ Cut your weekly reporting from 4 hours to 15 minutes"——**与 kit references 的 Counter-example 模式完全同构**（kit 每条规则带 Counter-example，hallmark 每规则带 ❌✅）。
6. **显式冲突优先级**："When a rule here conflicts with a framework default, this file wins. When the user's explicit prompt conflicts with a rule, the user wins."——与 kit AGENTS"冲突时以 AGENTS.md 与冻结文档为准"同款双层优先级。
7. **Companion 互链**：redesign-skill 姊妹仓分工（"It diagnoses… defers to this file for every concrete value"）——与 kit 技能路由互链同构。
