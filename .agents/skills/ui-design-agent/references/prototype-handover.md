# Prototype Handover Protocol（原型交接协议）

> 定位：初版原型的交付标准——**给客户看颜值，给开发留插槽**。原型的成功
> 不止于"好看能点"；业务工程师接手时若发现假数据写死在组件里、缩放即崩、
> 只有 happy path，原型就会被整体重写，工作流的信任随之归零。
> 一句话标准：**UI 纯展现，数据单口出入。**
> 来源：用户裁决（2026-10-03「业务解耦与交接标准」三层隔离协议+三道轻门），
> 与 dark-surface-standards（语义 token 双值禁硬编码）、copy-contract
> （空态/错误态文案）同源衔接。

## 1. 数据单口（Mock Isolation）

- **规则**：页面渲染的一切动态内容（表格行/列表项/头像/统计值/文本字段）
  必须绑定自单一数据文件（如 `mock_data.json`）；组件树内零硬编码业务数据。
  数据文件头部以注释写明每字段：名称/类型/单位/示例值（即接口字段草案）。
- **接手姿态**：业务工程师只需把 mock 绑定替换为真实 API 调用，样式与结构
  代码零改动——这是"业务准备就绪"的判据。
- 反例：`<td>38%</td>` 写死在 JSX；同一用户头像 URL 散落四个组件；中文文案
  与数据拼接在 render 里。
- 正例：`<StatCard value={data.conversion.rate} />`；全页动态内容可追溯至
  mock_data.json 的唯一端口。

## 2. 语义组件与 token 绑定（Design System Slots）

- **规则**：新原型默认绑定开源组件基建并全量语义 token——默认推荐
  **shadcn/ui + Tailwind 语义类**（`bg-primary`/`text-muted-foreground`/
  `<Button variant="primary">`）；配色/间距/字号禁止自由 hex 与魔法数，
  一律走语义变量（与 design-contract token 结构、dark-surface 双值纪律同源）。
- **为什么**：语义绑定使业务团队的私有组件库/主题可**一对一属性平替**；
  自由 hex 原型在第一次改主题时崩溃。
- **既有栈例外**：preserve-stack 纪律优先——存量 Vue/其他栈项目按其既有
  token 体系完成语义化即可，不强行迁移 shadcn。**语义绑定是本质，具体库是
  新原型的默认**。
- 反例：`style={{ color: "#3a7bd5" }}`、`padding: 13px`。
- 正例：token 表驱动 + 组件 variant API。

## 3. 四态必备（The 4 Essential States）

- **规则**：列表/表格/卡片流类页面必须提供**四态纯静态切换**（构建期常量
  切换即可，不要求真实异步）：
  1. **正常态**——满数据渲染（给客户看颜值的主视图）；
  2. **加载态**——skeleton 骨架，形状与正常态逐块一致；
  3. **空态**——占位 + 行动邀请（文案契约空态规则：裸"暂无数据"不算空态）；
  4. **错误态**——原因+修复双通道报错卡（文案契约错误规则）。
- 表单类页面至少提供默认态+校验错误态；详情页至少默认态+空态。
- **切换入口**：URL 参数（如 `?state=empty`）或 dev 开关；验收时四态逐态
  截图入证据（门E / D10 复核门适用）。
- 反例：只有 happy path——领导看完一缩放、一断网、一清库全露馅。

## 4. 交接文档 API_CONTRACT.md

- **规则**：原型交付**同笔**产出 `API_CONTRACT.md`——逐页面列出数据需求
  草案：实体/字段/类型/来源动作（"用户列表：id, name, avatar ← GET /api/
  users"；"统计卡：total, change_rate ← GET /api/stats"）。可直接由
  mock_data.json 转写导出。
- **接手顺序从此确定**：替换数据源 → 接接口 → 删 mock。后端的入参出参
  草案已由原型定好。

## 5. 三道轻门禁（交接信任的最小集）

原型类交付不强制全量单测与全量 a11y 扫描（那是门E 完整验收的尺度）；
以下三道轻门是**交接前必须过**的最小集：

1. **构建门**：极速编译通过（`vite build` 级别）——语法错误、幻觉 npm 包
   （不存在的依赖）在此拦截；
2. **反幻觉 lint**：`npm run lint:detail`（transition:all 禁令+
   will-change 白名单）已有；负 margin 滥用/未闭合标签/编造 CSS 类名在
   构建门与浏览器 console 检查中一并核验；
3. **规格门**：API_CONTRACT.md 存在，且字段与 mock_data.json 实际结构一致
   —— `npm run lint:spec -- --dir <原型目录>`（宽松匹配：全点路径或叶子名
   任一出现即算登记；报"整字段全文无踪影"的真断点）；无工具环境时人工对照。

## 6. 与门径的关系（不改变停点规则）

- **门D（契约）**：DESIGN.md 增「数据与状态」节——数据单口声明+四态清单；
- **交付物**：`mock_data.json` + `API_CONTRACT.md` 随原型同笔交付（外部
  工作区产物，不入库——产物边界见 architecture.md）；
- **门E（验收）**：四态逐态截图+构建门/lint 通过记录入验收证据；
- 本协议规定的是"过门的东西长什么样"，不新增门、不新增裁决类型。
