# Tempo Day 产品规划

## 一句话构想

一个把一天切成可执行节奏，让自由职业者知道现在该做什么的专注工作台。

## 用户与核心任务

用户是独立工作的自由职业者。最短闭环是：记录任务及预计分钟 → 选中一个任务 → 开始/暂停专注 → 完成 → 查看剩余任务。能新增和编辑自己的计划，不局限于演示数据。

## 范围

第一版交付可运行的本地前端，不含账号、服务端、支付、多人协作或通知权限。任务和截止时间存入 localStorage；页面刷新与后台恢复通过截止时间计算余量，不按 interval 次数扣时。

## 首屏结构

- 顶部：品牌、当天日期、本地保存状态。
- 桌面：左侧任务队列，中间当前任务和计时器，右侧今日汇总。首屏不是介绍页。
- 手机：当前任务和主操作优先，任务队列在下方。汇总保持紧凑。
- 模式切换：今日工作台 / 专注视图。专注视图隐藏次要信息，保留退出路径和计时状态。

## 关键状态

待开始、计时中、已暂停、时间到、已完成；没有任务时的空状态；全部完成状态；新增/编辑表单及校验；删除和完成后的撤销；存储不可用提醒。切换任务会保留原任务剩余时间。

## 组件

AppHeader、ViewSwitch、TaskQueue、TaskEditor、CurrentSession、SessionTimeline、DaySummary、Toast、EmptyState。

## 视觉与动效契约

- Operate 模式，安静的白底工作界面。石墨文本、绿色主操作、蓝色进度、黄褐色休息分类。强调真实数据而非装饰卡片。
- 4/8px 间距系统，8px 最大框架圆角；正文 16px、小标签 14px，标题 24–32px；不随 viewport 缩放字体。
- 模式指示器与选择状态使用 shared layoutId，Snappy spring：stiffness 400、damping 30、mass 0.8。
- 当前任务更换通过 AnimatePresence 轻微淡入/位移，语义状态即时更新，不等动画完成才接受操作。
- 完成任务时队列保持位置连续，主控按钮 press 0.98；不对每次计时重放入场动画。
- reduced-motion：无位移、缩放或循环动效，状态立即更新。

## 验收条件

1. 创建/编辑任务、计时开始/暂停/恢复、完成/撤销、切换视图和刷新恢复均能实际工作。
2. 计时按 endAt 时间戳恢复，后台标签页不导致累计误差。
3. 390、768、1440px 浏览器截图无横向溢出、按钮遮挡或文字重叠。
4. Tab 可到达主操作，表单标签清楚；减少动效下功能与语义状态一致。
5. npm run build 与定向逻辑测试通过；保存控制台与截图证据。
6. 先做一次批量浏览器观察，再按观察批量修复，最后确认；不把静态检查叫做视觉质量证明。

## 已知推断与流程边界

用户委派了从一句话直接做产品，没有提供设计图或品牌约束。名称、样例任务、颜色和具体布局是可替换的产品推断，不是用户确认的设计稿。该试作不声称图像还原率。

目标工作区原本不存在。Impeccable context 已在目标目录执行，父仓库只作为技能与规则来源。独立浏览器截图和日志只写到本项目 artifacts 目录。
