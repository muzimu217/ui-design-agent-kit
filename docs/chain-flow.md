## 三、三个确认门（用户操作方式）

1. **确认门① 素材选择**（环节 3，强制）：主代理把候选素材整理成清单（每项：
   来源 URL、用途、截图或描述、授权状态），发用户；用户勾选"要/不要"；
   **只有用户选中的素材才允许在环节 4 引入**。未选素材不得进入实现。
2. **确认门② 契约确认**（环节 5，大项目/动效复杂时强制）：设计契约 + 动效
   方案（交互反馈、动态流转、背景动画的具体规格）发用户确认；用户可要求
   调整基调或动效强度。
3. **确认门③ 成品验收**（环节 8，强制）：预览 URL + 验收记录（含每环节执行
   者）发用户；用户确认通过才入库，未通过则进入**一次有证据的修改循环**
   （按 acceptance.md：批量检查 → 批量修复 → 确认）。

规则：**未过确认门，不得进入下一环节**。确认门是流程的闸门，不是装饰。

## 四、动效规格与 MCP 调用点

用户反馈"缺交互感、动态流转感、背景动画"——v2 在环节 6/7 强制动效规格：

| 动效类型 | 规格要求 | 实现能力 | MCP/工具调用点 |
| --- | --- | --- | --- |
| 交互反馈 | hover/press ≤150ms、spring 或 ≤150ms 过渡、禁用 transition:all | motion/react 或 CSS | Motion MCP `generate-css-easing`（真实取 CSS 弹簧曲线） |
| 动态流转 | 状态切换的空间连续性（共享布局、AnimatePresence、级联 40-80ms） | motion/react | Motion MCP `search-motion-docs`（按概念查文档资源，如 shared layout） |
| 背景动画 | 克制的光影/网格/渐变流动，reduced-motion 降级为静态 | CSS 或 motion/react | Motion 文档检索 + 浏览器证据 |
| 视频/时间轴（仅视频任务） | frame 时钟、确定性时间轴 | Remotion | `remotion-video-agent` + 官方 Remotion skills |

**边界澄清（重要）**：网页 UI 的动态流转/背景动画走 **Motion**（motion.dev +
Motion MCP 的两个真实工具：`search-motion-docs`、`generate-css-easing`）；
**Remotion 是视频/时间轴渲染工具，不用于网页交互动画**（kit tool-routing 明确
"Web UI: motion/react 或 CSS；Video render: remotion"）。调 Remotion 解决网页
动效是错误路由。

动效验收（环节 7）：normal 模式实测 + `prefers-reduced-motion` 模式实测 +
快速反向/中断断言；背景动画需提供帧序列或录屏证据，仅截图不算动态证据。
