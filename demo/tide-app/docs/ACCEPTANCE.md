## 一、第一轮审核的失职（如实登记）

第一轮我给出了"通过"，但**成品实际上有明显缺陷**。失职点：

| 我检查的 | 我漏掉的 |
| --- | --- |
| DOM 里存在 `.scenario-item`（3 个） | **它们 `opacity: 0`，视觉上完全不可见** |
| 对比度、键盘、触控尺寸等指标 | **页面本身好不好看、有没有内容** |
| 曲线路径存在、无 NaN | **曲线是锯齿折线，不是平滑曲线** |

**根因**：我的验证全是"结构断言"——元素在不在 DOM、数值对不对。**没有一条检查"用户能不能看见"**。`scenarioItemCount: 3` 让我判定通过，而真实情况是用户看到一片空白。

这是审核方法的缺陷，不是运气问题。

## 二、第二轮发现的真实缺陷

| # | 缺陷 | 严重度 | 证据 |
| --- | --- | --- | --- |
| 1 | 第三屏与场景卡内容 `opacity: 0` 永久不可见 | **P0** | DOM 断言 `style="opacity: 0; filter: blur(4px)"`；入场动画未触发 |
| 2 | 曲线是锯齿折线（`L` 逐点连接） | **P1** | 路径 `M0 137.45 L2.42 137.23 L4.83…` 无贝塞尔段 |
| 3 | 低潮标注「12:20 0.09」压住「12:00」刻度 | **P1** | 截图可见；标注 `top` 落在内区下沿，与刻度行重叠 |
| 4 | 首屏 `min-height:100svh` + 居中 → 上下大片空白 | **P1** | hero 内容仅约 380px，视口 900px |
| 5 | 全页零图像、场景卡纯文字堆叠 | **P1** | 视觉上"简单普通" |

## 三、修复

| # | 修复 | 实现位置 |
| --- | --- | --- |
| 1 | 入场动画不再把内容初始设为不可见；只做 10px 位移增强 | `App.tsx` 两处 `motion.li` |
| 2 | Catmull-Rom 样条转三次贝塞尔，曲线精确穿过每个采样点且平滑 | `curve.ts` `buildSmoothPath` |
| 3 | 新增 `--plot-inset-bottom`（2.75rem > 上带 1.875rem），下留白带加高一行 | `styles.css` |
| 4 | 首屏改为按内容排版，右侧放整日潮位波形 | `App.tsx` `Hero`、`styles.css` `.hero-grid` |
| 5 | 首屏加整日波形；每张场景卡加当日波形 + 该场景时段高亮 | `curve.ts` `buildSparkline` / `buildScenarioSpark` |

**关于第 5 项的取舍说明**：波形是**数据**不是装饰——它与主曲线用同一份数据、同一套平滑算法，场景卡的高亮段直接来自该卡数值的来源（海钓=涨潮窗口、赶海=低潮窗口、摄影=最高潮位）。这样卡片能"指出"自己在讲曲线上的哪一段，而不是放一张与数据无关的配图。

## 四、门禁加强（这是本轮最重要的产出）

第一轮的检查脚本**结构上无法发现**上述缺陷。本轮新增 5 条门禁，全部静态可判定：

| 门 | 检查 | 能抓住 |
| --- | --- | --- |
| QG25 | 内容不得靠动画才可见（`initial` 不得含 `opacity: 0`） | 缺陷 1 |
| QG26 | 入场不得用 `blur()` 遮内容 | 缺陷 1 |
| QG27 | 场景卡必须含数据图形（`.scenario-spark` + `buildScenarioSpark`） | 缺陷 5 |
| QG28 | 首屏必须有数据波形作视觉主体（`.hero-spark` + `buildSparkline`） | 缺陷 4/5 |
| QG29 | 首屏不得用 `min-height:100svh` 居中 | 缺陷 4 |

**验证门禁本身有效**：把 `opacity: 0` 改回去，QG25 立即 FAIL。

实测结果：**静态检查 19/19 通过**（第一轮是 14/14，但那 14 条全都没覆盖真实缺陷）。

**同时修了脚本自身两处范围错误**（都属于"注释里说明不用 X 被判为用了 X"）：
- 扫到 `docs/` 目录（方向稿本来就该讨论"预报"）
- 扫到 `.test.ts` 文件（断言里含 `display:none` 字符串）

现已排除注释、文档目录与测试文件。
