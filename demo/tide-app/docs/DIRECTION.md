# 潮汐 TIDE · 方向稿（门A）

> 本文件是「初步设计稿」环节的产物：视觉基调、页面结构草案、动效意图。
> 按链路规则，此阶段**不写实现代码**。用户确认本稿后才进入素材调研。

## 一、任务理解

- **产品**：潮汐 TIDE —— 面向海钓与赶海人群的潮汐预报产品页
- **用户**：周末出海钓鱼的人、带孩子赶海的家长；他们关心"几点退潮、几点能下水"
- **主要任务**：让访客在 10 秒内看懂"这个 App 能告诉我今天什么时候能下水"，并愿意试
- **第一版范围**：单页产品页 + 一个可真实交互的潮汐曲线
- **非目标**：不做账号、不做真实潮汐数据接入（演示数据）、不做多语言

## 二、为什么选这个题材

现有 9 个 demo 覆盖运营台、3D 游戏、手机产品页、博客、效率工具，**没有一个是"数据随时间的自然节律"这类题材**。潮汐的特点是：它的美来自真实数据形态（一天两次涨落、月相影响），而不是来自装饰。这能检验视觉方向是否服务于数据本身。

## 三、视觉基调

**方向：深海底蓝 + 潮线荧光青，像看一块被水浸过的仪器面板。**

- 深色为主（#071a24 一类），因为赶海人凌晨看手机、海钓人多在户外强光下——深底配高对比数据线比浅底更耐看
- 单一强调色：潮线青（#3fd6c8 一类），只用在"数据"和"当前时间"上，不用在装饰上
- 不用渐变球、不用玻璃拟态堆叠——那些是 AI 味最重的信号
- 数字用等宽字体，因为潮位是读数

**具名基线**：`awesome-design-md` 的 `linear.app` 与 `vercel`（深色高对比、克制强调色、数据优先）。授权：MIT 分析文档，改编关系不照搬。

## 四、页面结构草案

```
1  顶部     品牌 + 一句价值主张 + "看今天的潮汐" 主按钮
2  核心     潮汐曲线（可拖动时间轴）+ 当前潮位读数
3  节律     一日两次涨落的说明（用真实曲线形态讲，不用图标堆）
4  场景     海钓 / 赶海 / 摄影 三个使用场景（横排，克制）
5  结尾     下载引导（演示性质，标注为演示）
```

**结构理由**：核心交互放在第二屏，因为它是这个产品唯一不可替代的东西。常见做法是把 hero 做成大图，但这个产品的 hero 就是那条曲线本身。

## 五、动效意图

- 曲线入场：从左到右描线（draw-on），让数据"被画出来"而不是"跳出来"
- 拖动时间轴：读数与曲线游标**弹簧跟随**，不是线性插值
- 当前时刻标记：缓慢脉冲，唯一允许的循环动画
- 全部遵循 `motion-contract.md`：弹簧预设、`prefers-reduced-motion` 下降级为静态

## 六、风险与未知

- **待确认**：潮汐数据用演示数据（正弦叠加模拟半日潮）是否可以？还是需要接真实公开数据源？
- **待确认**：受众是中文为主还是中英双语？（影响文案与字体）
- **已知限制**：不接真实数据时，"预报"二字需要谨慎使用，页面上应标注为演示数据

## 七、需要用户裁决的点（门A）

1. 方向是否认可（深海底蓝 + 潮线青 + 曲线为核心）
2. 演示数据是否可以接受
3. 是否有需要保留/避免的具体元素
