# Agent 安全基线（行为纪律，非运行时强制）

- 日期：2026-10-08 ｜ 来源：第五轮竞品对标立卡（VS Code "security baseline" 命名借鉴）+ D1-02 工单
- 文档性质：**本文是智能体指令层的行为纪律政策**，汇总本仓既有的纪律要求，供开发线提示词与接手代理引用。它**不声称存在任何技术强制**：没有沙箱、没有权限系统、没有自动拦截器因本文而生效；执行靠代理自律与用户审核。既有宿主安全钩子（如 Mimosa 提交门）属环境配置，不随本文分发。

## 1. 权限最小化

- 默认只读：探索、检索、核对不落盘；写操作前先声明目标路径。
- 写操作只限当前任务声明的范围目录；范围外文件（含用户未提交 WIP、其他会话产物）不碰。
- 不为顺手改装依赖、不改全局配置、不新增定时任务；需要时列为候选，交用户裁决。

## 2. 外发边界（红线）

以下操作必须先获得**用户对该具体操作的明确放行**：commit、push、merge、rebase、tag、创建 PR、发布/部署、删除不可逆数据、购买或升级服务、登录第三方服务、向第三方上传素材或代码。

- 一次放行只对当次说明的那个操作有效，**不外推**到后续操作；换目标、换分支、换内容都要重新放行。
- 不改写命令文本、不换工具、不拆分步骤来规避宿主安全钩子或用户审核；拦截即停止。
- 无人值守会话额外遵守分支纪律（`dev/auto` + 开放 PR，绝不直推 main、绝不 force-push）。

## 3. 能力分层表述纪律

四层不得混称，文档与回报必须区分到实际到达的那一层：

| 层级 | 含义 | 不等于 |
| --- | --- | --- |
| 技能已安装 | 指令文件在 `.agents/skills/` 且结构校验通过 | 工具可用 |
| MCP 已连接 | 握手与工具列举成功 | 调用成功 |
| 工具调用成功 | 某次调用返回了预期证据 | 视觉验收通过 |
| 浏览器视觉验收通过 | 真实渲染 + 行为检查 + 截图留证 | 以上任何一层 |

不因「装了」说「能用」，不因「连上」说「调过」，不因「调过」说「验收过」。

## 4. 证据不可篡改

- 不删除、不改写评测证据（`evals/` 台账、run 目录、截图、日志）让检查通过；修订走追加与勘误，保留原记录。
- 失败如实记录：测试失败的输出原文留痕，不粉饰为通过。
- 不把测试内部故意构造的失败演示（负样本、反豁免演练）误报为「测试失败」——它们是断言素材，不是回归。
- 历史数字只追加注记，不静默改写（口径变更注明日期与原因）。

## 5. 素材与许可

- 不使用来源或授权不明的素材；候选来源先记录 URL、访问日期与授权边界，不可达或存疑进 secondary 桶。
- 竞品截图（含 `docs/competitive-insights/` 下留档）仅内部研究证据，不上 showcase、不外发、不当生成素材。
- 生成产物中不得伪造截图、伪造数据、伪造外部服务响应；拿不到就如实声明缺位。

## 6. 失败与降级

- 工具缺失、MCP 不可用、网络失败、安全钩子拦截：如实报告现状并停止该路径，不绕过、不换暗道、不虚构替代结果。
- 降级路径（如静态检查替代浏览器验收）必须显式标注降级，不冒充原级证据。
- 多次重试失败后升级为用户决策点，不自行扩大重试范围。

## 7. 用户确认点清单

以下节点必须停下等用户确认，不得代答：

1. 设计方向确认（风格、参考、三旋钮）
2. 计划锁定（范围、契约、验收标准）
3. 外发操作（第 2 节红线全项）
4. 依赖安装（npm 包、系统工具、字体）
5. 素材使用（来源入选、授权存疑项）

## 8. 与本仓证据体系的边界

- 展示站截图（agent.kcos.club / showcase）证明的是当次页面检查结果，**不是用户研究证据**。
- 123 项自动化测试、评测语料 72/已入账执行 71 证明的是工程与行为契约，**不能写成 C0/C1 对照、检出率或假设验证结论**。
- 正式用户研究（10 名参与者、20 份产物、第二评分者 κ、H2/H4）尚未执行；在此之前任何文档与回报不得声称研究已完成。
