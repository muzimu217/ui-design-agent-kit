# 对标洞察：bolt.new（StackBlitz）——第二轮学习循环

- 日期：2026-10-07 ｜ 检视级别：**unverified-partial**（实看落地页一张截图 + DOM 文本探查；未注册实跑生成）
- 证据：`landing.png`

## 机制观察（首屏 DOM 实据）

1. 提示框旁自带两个按钮：**"Select design system"** 与 **"Plan"**——生成前即可钉设计系统、切规划模式。
2. 模型档位选择器直接标 **Intelligence: Very high / Token cost: High**——把"质量-成本交换率"做成用户可见的显式选择。

## 对照（与 v0/与我们）

| 机制 | v0 有无 | 我们现状 | 解读 |
| --- | --- | --- | --- |
| 生成前选设计系统 | 无（靠 prompt 里说） | 门 B+品味档案（更重但更可溯源） | **竞品在向"前置控制"演化**——市场在自发逼近我们的门设计，旁证 RQ-A 前提 |
| Plan 模式开关 | 无 | W3 计划锁定（强制，人裁决） | 他们做成可选便利，我们做成强制门——差异化在"可信"不在"丝滑" |
| 质量/成本显式档位 | 无 | H4（质量—注意力交换率）是研究指标 | 他们把它商品化了；我们把它**量化进论文**——同一问题两种回答 |

## 可借鉴

- 把"选设计系统"做成 C1 条件内**秒级操作**（P1 实证：门耗时意愿分化，厌烦格式化/环境类门——设计系统选择恰属用户愿意花的门），供任务卡 C1 交互稿参考（立卡，随门 A 走）。

## 不抄

- 自动档位直接烧 token 换质量；我们的证据分级+人工门是更诚实的控制方式。
