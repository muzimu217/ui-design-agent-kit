## 一、逐点评估

### X1 "纯 Prompt 饰 conglomerate 套壳"——**部分落地（定位问题，非实质问题）**

| 原文指控 | 本仓实况 | 证据 |
| --- | --- | --- |
| "大概率是几个 Markdown 文件" | 指令层确实是 Markdown（SKILL.md+references）；但仓库另有：160 项自动化测试（行为契约/文档漂移守卫/链审计/仪器 65 项）、71 场景评测语料+逐场证据台账、部署管线、8 个线上 demo | `tests/`、`evals/results.json`、`npm test` |
| "LangChain 全家桶/几百兆 node_modules" | 零 LangChain；根依赖仅验证工具链（playwright/express 供 doctor 与浏览器取证） | `package.json` |
| "无核心单测" | 有，且含本批评点名的复杂场景：12 列台账（T2）、500 行虚拟列表（T3）在任务池；暗面对比度缺陷谱 21 批审计留痕 | `evals/runs/`、`docs/quality-monitor.md` |

**落地的部分**：名字叫 "Agent Kit"，暗示运行时引擎/自动编排；实际核心是**指令层+研究仪器**。名字与内容的错位是真的，README 首屏没有诚实能力矩阵（是什么/不是什么）。

### X2 "脱离 Figma 与前端规范"——**半落地（范围选择未说清，但有实质集成）**

- 原文说"没有任何 Figma 能力"——部分真：figma MCP 配置存在但**有意禁用**（AGENTS.md 明示）。
- 但"跟企业设计规范完全脱节"**不实**：设计源进入走 **designContracts**（awesome-design-md 品牌设计基线，lock 钉 revision + 按需取用）与 uak-design-system 本地检索（79 风格/192 配色/74 字体对/119 UX 指南）——这是"设计契约输入"的真实通道，只是不走 Figma 协议。证据：`tooling/sources.lock.json`、`.agents/skills/uak-design-system/`。
- "产出捏造 Hex/幽灵组件库"恰是本仓评测抓真实缺陷的领域（暗面对比度家族=历史最高频缺陷类别，21 批审计）——批评描述的病，本仓的评测台账里全有病历。

### X3 "已被 IDE 原生代偿，无独立价值"——**不落地，且与我们的数据相反**

这是最核心的一条，值得认真回应：

- 原文前提："主流大模型原生就能输出极高水准的代码"。
- 我们的 P1 证据（5 份真人语料）：**原生生成的失败恰好不在"生成质量"，而在验证维度**——E-01（全栈 5 年）：假数据写死/开关无状态/移动端溢出事后才发现；E-02：假导出弹窗/破图/按钮被遮；E-03：对比度 3:1 不足/焦点隐身。FM-02（自述盲信）5/5 全员。
- 即：**"模型原生很强"与我们一致；但"所以不需要独立工作流"推不出来**——生成越强，人的验收盲区越是瓶颈。这正是 RQ-A 的立足点。此条批评实际上是我们研究动机的免费佐证。
- "独立 CLI 反人类"——同意一半：作为**产品**形态成立；作为**研究仪器**（强制条件分配/门禁/证据链，Cursor 不会给用户上锁）不成立。仪器与 IDE 天然不冲突。

### X4 "工程虚胖/commit 自嗨/幻觉组件库"——**基本不落地**

- commit 历史：`git log` 可查——批量审计整改、技能钉版、测试守卫，非 typo 流水账。
- "无端到端构建测试"：五级证据等级制度（Installed≠Configured≠Connected≠Called≠VisuallyVerified）+ 浏览器实测强制 + 未实测不得声称——**这个 kit 的存在理由就是 X4 描述的病**。证据：`docs/architecture.md` Evidence Levels 表、`docs/gates.md`。

### X5 "社区灌水/营销大于内容"——**落地（研究定位下可接受，产品定位下致命）**

- 真：单人研究仓，issue 区是反馈模板而非深度技术讨论；无生产环境用户反馈 token 消耗/组件冲突类 issue。
- 诚实归因：这是**定位问题第三次出现**——它不是产品，还没到该有产品社区的阶段；但门面没说清，读者会按产品标准审它，然后得出 X5。

## 二、判定汇总

| 指控 | 判定 | 一句话 |
| --- | --- | --- |
| X1 套壳 | **半落地** | 实质不是套壳，但命名与门面让它**看起来**是 |
| X2 脱节 | **半落地** | Figma 无集成是真的（有意禁用）；designContracts 通道存在但没说 |
| X3 被代偿 | **不落地** | 与 P1 数据相反；生成强≠验证不需要——恰是 RQ-A 立足点 |
| X4 虚胖 | **不落地** | 160 测试/证据等级制/审计台账与指控相反 |
| X5 社区 | **落地** | 研究仓无产品社区是常态，但门面没按研究仓自我介绍 |

**共识点**：批评与我们的研究在"原生模型已很强"上其实一致；分歧只在"因此不需要什么"。我们的答案（人验证是瓶颈）有数据，它的答案（什么都不需要）没有。

## 三、重构提案（在测试分支执行，呈用户裁决）

**共同前提**：面分支 `experiment/uak-paper` 冻结（本人不再提交/合并）；全部后续开发在 `test/uak-p2-restructure` 分支。

### 方案 A：门面与定位重构（轻，推荐首选）

1. README 首屏改为**研究优先定位**：这是一个"用可证据化的工作流研究 AI 界面构建中人工监督价值"的研究仓，附带一套生产可用的指令层；**诚实能力矩阵**（是：指令层/评测/仪器/证据制度；不是：运行时引擎/Figma 同步/组件库/IDE 替代品）。
2. 设计源集成边界写明：Figma 有意禁用，设计契约走 designContracts 钉版通道。
3. 目录分层导读图（指令层/研究层/demo 隔离层/工具层），引用 `research/architecture.md`。
4. 成本：纯文档，1 个提交，零测试风险。

### 方案 B：目录物理重组（中）

kit 指令层收拢独立顶层、研究层独立、demo 隔离强化；160 项测试路径全跟。成本高（全仓路径变更+守卫重接），收益主要是观感——**建议仅在 A 不足以回应时做**。

### 方案 C：拆仓（重）

研究仪器独立仓库。用户 2026-10-01 已裁定当前仓改造、不另立仓——**除非翻案，否则不做**。

**推荐：先 A**。批评真正命中的是"定位诚实度"而非"工程实质"；A 用最低成本把名字与内容的错位治掉。B/C 等 A 落地后看是否仍需要。
