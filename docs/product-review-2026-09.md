> 定位：产品设计师视角的项目评审——只做思考与规划，不含开发。
> 方法：真实访客体检（agent.kcos.club / GitHub 门面）+ 外部定位调研（v0/bolt/lovable

## 一、这个产品到底是什么（一句话）

**给"AI 生成 UI"补上缺失的验收层**：v0 / bolt / lovable 们在比赛"谁生成得更快更好看"，
UAK 不跟那条赛道——它系统化解决的是所有人都没解决的问题：**智能体说"做完了"，你怎么信？**

三件套构成回答：六道人工确认门（A–F）、五级证据阶梯（终于"视觉验证"才算了结）、
门账本（决策债一处可见）。论文（Zenodo DOI 10.5281/zenodo.22804947）是这套方法论的学术凭证。

## 二、核心用户与场景

| 用户 | 场景 | 现状匹配度 |
| --- | --- | --- |
| 用 Claude Code / Codex 做前端的开发者 | 想要"智能体交付的界面我能信、能验" | 核心匹配；但需要自建环境，上手有门槛 |
| 中小团队引入 AI 编码 | 需要"AI 产出可控"的流程与记录（合规向：EU AI Act Art.4 已要求受控采纳的证据） | 潜在主力；产品尚未对他们说话 |
| 学生/研究者（论文/大创） | 需要一个可引用、可复现的方法论 + 数据 | 论文+语料已备好；缺英文入口 |

外部调研佐证：v0/bolt/lovable 的公认短板是"产出更像原型而非生产级"；"AI Definition of
Done"正成为独立话语（含合规驱动的证据需求）——**没有产品把"验收"做成一等公民**。这是空白，
也是 UAK 唯一应该占的位置。

## 五、核心功能 vs 次要功能（资源该往哪灌）

**核心（护城河，只许加强）**：六门工作流、证据阶梯、门账本、评测语料与 rubric、
回放/门禁图作为"证据产物"的形态。它们互相咬合：语料喂论文，论文背工具，工具产证据。

**次要（服务核心，够用即可）**：showcase 视觉打磨、intro-video、灵感库/素材检索、
技能数量（gsap/remotion 等垂直技能）、更多 diagram 交互。

**明确不做**：
- 不做"生成能力"对标（那是 v0 们的赛道，烧钱且无胜算）
- 不做多平台客户端/托管服务（单人维护不可持续）
- 不碰上游运行时（既定裁定）；不买推广、不建引流群（社区口碑红线）

## 六、建议与路线（只规划；执行另等指令）

### P0 · 凭证接线（成本极低，本周可做）
1. 主干 README 回挂论文：DOI 徽章 + 一节"方法论文"（3 行，链接 Zenodo）。
   *性质是文档回填而非功能开发；与"主干不污染"的裁定不冲突——但执行前需你点头。*
2. 线上站加论文入口（showcase 仓一处链接 + 一行说明）。
3. 统一仓库口径：kit 仓为产品本体，showcase 仓在 README 首行声明"这是展示站，本体在 kit 仓"。
- 风险：几乎为零。收益：D1/D2 直接消除，论文开始被引用。

### P1 · 把"验收层"讲出去（1–2 周，借势窗口）
1. **叙事升级**：对外文案把"证据阶梯"对齐到正在成形的"AI Definition of Done / 受控
   AI 采纳证据"话语（EU AI Act Art.4 是合规顺风）——不是改产品，是改"说法"，让
   UAK 从"个人作品集工具"升格为"AI 交付的验收协议"。
2. **补执行样本**：60 语料执行 10–15 条（G2 回放协议落地），发布"通过率+失败分析"报告
   ——失败数据比全过更可信，直接回应 D5，同时是下一篇论文的数据。
3. **英文 README**：论文是英文的，研究者受众需要英文入口（最低成本的国际触达）。

### P2 · 结构性升级（月级，需人手）
1. 第二评分者一致性研究（论文升级的前置）。
2. workshop 投稿（CHI LBW / IUI companion 路线，见 `paper/submission/VENUES.md`）。
3. Zenodo–GitHub 集成发软件 DOI；release 节奏化。

## 七、诚实边界（本评审自身的）

- 站点体检是桌面单机视角，未覆盖移动端与无障碍的系统性走查（那属于开发性工作）。
- "空白"判断基于两次检索+既有认知，未做系统的竞品扫描；若要对外宣称"唯一"，需再做一轮。
- 所有"建议"均为规划，未动任何代码——执行清单在等指令。
