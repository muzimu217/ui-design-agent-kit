# 平台架构规格 v1（platform-architecture.md）

- 日期：2026-10-01 ｜ 状态：DRAFT——待用户审定（对应任务表 P2-5 + 全平台架构定义）
- 性质：**研究适配层规格，纯规格，零代码**。它把原 UAK 主架构（[`../docs/chain-flow.md`](../docs/chain-flow.md)）接入可比较的研究条件和证据记录；不替代原工作流。P3 依此实现研究仪器；实现不得静默偏离本规格，偏离须记修订。
- 上游：[plan-preregistration-v1.md](plan-preregistration-v1.md)（v1.0 冻结）｜[master-task-schedule.md](master-task-schedule.md)

## 0.1 与原 UAK 架构的关系

本文件不是第二套产品流程。原 UAK 的六阶段思维、计划/执行模式、门 A-F、MCP 留痕和多轮浏览器验收仍由 [`../docs/chain-flow.md`](../docs/chain-flow.md) 负责；本文件只定义研究如何把这些环节映射为 C0/C1 条件，并记录 R1-R5 仪器数据。总关系图见 [`architecture.md`](architecture.md)。

1. **研究优先**：仪器可信度 > 功能丰富度。硬 runner 存在的唯一理由是让实验数据可信。
2. **混合方案**（2026-09-30 用户裁定）：工作流走现指令层（SKILL.md 体系），代码只强制四件事——条件分配、门禁状态机、计时、证据落盘。
3. **可替换**：底层模型/代理可换，不是贡献点；知识层是被编排的上游能力，同样不是贡献点。
4. **runner 不评判**：runner 只记录，不打分；一切质量判断归人与评分者。
5. **复用不改动**：现有 22 技能、MCP 配置、sources.lock 钉版原样复用；不修改任何上游资产。

## 1. 架构总览

```text
参与者（前端开发者 / 非专家构建者）
  │ 口语需求
  ▼
┌──────────── 调度层（指令层实现，C1 条件）────────────┐
│ W1 意图分析器 → 需求卡 ──⛩门1 方向（人裁决）          │
│ W2 检索规划器 → 素材候选 ──⛩门2 素材（人勾选+许可）    │
│ W3 计划锁定（revision 冻结）                          │
│ W4 执行器（可替换模型/子代理，有界派发）                │
│ W5 验收与证据（浏览器实测+分级证据+P0/P1/P2 清单）      │
│    ──⛩门3 验收（人裁决，多轮）                        │
└─────────────────────────────────────────────────┘
  ▲ 检索                      │ 产物/证据
┌─┴──────────────┐      ┌─────▼──────────────┐
│ 知识层（可选组件）│      │ 产物工作区（隔离）    │
│ 钉版语料+统一检索 │      │ 独立目录，不回流仓库  │
└────────────────┘      └────────────────────┘
┌────────── 实验仪器层（硬 runner，代码强制，全程不经 AI）──────────┐
│ R1 条件分配器 · R2 门禁状态机 · R3 计时器 · R4 日志器 · R5 证据落盘 │
└────────────────────────────────────────────────────────────┘
```

C0（裸 prompt 基线）只经过：参与者 ↔ 模型的自由对话 + R1/R3/R4/R5 的旁路记录（见 §5）。

## 2. 调度层模块（指令层，C1 条件内）

| 模块 | 输入 → 输出 | 停点 |
| --- | --- | --- |
| W1 意图分析器 | 口语需求 → **需求卡**（见 §2.1 schema） | ⛩门1：用户确认/修改需求卡 |
| W2 检索规划器 | 需求卡 → 检索计划 → 知识层查询 → 候选清单 | ⛩门2：用户勾选素材 |
| W3 计划锁定 | 已确认需求+素材 → 计划 revision rN（冻结） | 执行请求只对已锁 revision 有效 |
| W4 执行器 | 计划 → 代码/页面（外部工作区）；1 主代理+≤1 活跃子代理 | — |
| W5 验收与证据 | 产物 → 分级证据包+逐项问题清单（P0/P1/P2） | ⛩门3：用户逐轮裁决；未修 P0 不得宣称完成 |

**2.1 需求卡 schema（W1 输出，v1）**

```json
{
  "mission": "一句话目标",
  "audience": "使用者与场景",
  "mainFlow": ["主链路步骤"],
  "nonGoals": ["明确不做的"],
  "openQuestions": ["待用户确认的问题（随卡呈交）"],
  "viewport": ["桌面/移动"],
  "acceptanceOutline": ["粗粒度验收点"],
  "taskLevel": "S|M|L"
}
```

**任务分级**：S 跳过门1/门2（仅一轮有证据验收）；M 走门1-lite/门2（有外部素材才过）/门3 全量；L 全链。实验任务卡预 assigned 等级，不许参与者或 AI 改级。

**计划失效（stale）规则**：品牌/范围/选定素材/原型 brief 变更 → 计划标 stale，回受影响最早决策；纯实现缺陷保持锁定走局部修复。

## 3. 门禁状态机（R2 强制，调度层只请求不决定）

```text
idle → intent_drafting → GATE1_PENDING →(人:approve)→ material_search
     → GATE2_PENDING →(人:approve)→ plan_frozen →(执行请求)→ executing
     → evidence_collect → GATE3_PENDING →(人:approve / 每轮)→ done
任意 PENDING 态：(人:reject) → 回对应 drafting 态（记录回退原因）
plan_frozen 后变更方向类输入 → stale → 回 material_search 或 intent_drafting
```

- **唯一写者**：门禁状态只能由 R2 改写；调度层/模型只能发 `request_transition`，R2 校验后落账。AI 永远无法自行过门——这是混合方案的核心承诺。
- 每次转换记录：`{state, from, to, actor: user|agent|runner, ts, taskLevel, gateDecisionId}`。
- M 任务走 lite 门：门1 需求卡可简化为 mission+openQuestions；门2 仅当检索计划非空。

## 4. 实验仪器层（最小硬 runner 规格，P3 实现）

| 模块 | 职责 | 关键约束 |
| --- | --- | --- |
| R1 条件分配器 | 参与者×任务×条件 的拉丁方分配表 | 表一旦生成**不可变**；平衡条件顺序与任务搭配 |
| R2 门禁状态机 | §3 状态的唯一执行者 | 门禁决策仅接受显式人工输入事件 |
| R3 计时器 | 阶段时间戳：每门 pending→决策间隔（人工监督时间）、执行段时长、总时长 | 挂钟时间+每门停留；C0 的时间见 §5 |
| R4 日志器 | 结构化事件流（人的门动作、AI 派发/完成、异常） | append-only JSONL；事件 schema 见 §4.1 |
| R5 证据落盘器 | 每次任务运行的全部工件归档（§6 目录规范） | 写入即带 sha256 清单；分析前冻结 |

**4.1 事件 schema（JSONL，每行一事）**

```json
{"ts":"ISO8601","runId":"p03-T6-C1","seq":42,"actor":"user|agent|runner",
 "type":"gate_decision|gate_request|dispatch|artifact_saved|exception|…",
 "payload":{…}, "prevSha":"链式哈希，防篡改"}
```

**4.2 运行形态**：CLI 包装器 vs 本地常驻服务——**P3 定**，本规格只约束行为（状态唯一写者、append-only、不可变分配表）。

## 5. 条件接线与公平性控制

| 维度 | C0 裸 prompt | C1 门控工作流 |
| --- | --- | --- |
| 交互 | 参与者与同一模型自由对话，自行决定验收方式与终点 | §2 全链；门由 R2 强制 |
| 相同点 | 同一模型版本、同一任务卡文本、60 分钟时限、同一评分（盲评） | 同左 |
| 计时 | AI 侧事件由 R4 记录；**人工时间**=录屏+评分者事后编码（如实声明为编码法） | R3 自动分段计时 |
| 操纵检查 | 会话日志确认 C0 无门禁提示泄漏 | R2 状态轨迹完整 |

**泄漏防护**：C0 任务材料中不得出现"门/证据等级/计划锁定"等引导词；两条件共用模型配置由 R1 分发，参与者只见到任务卡。

## 6. 产物与证据目录规范

```text
runs/
  p{01..10}/                 # 参与者（匿名编号）
    T{n}-{C0|C1}/            # 任务×条件
      input/task-card.md     # 呈现给参与者的任务文本（冻结版）
      gates/*.json           # 门决策记录（C1）
      plan/                  # 需求卡/计划 revision（C1）
      worktree-diff/         # 代码变更
      evidence/              # 截图/实测输出/证据包 manifest
      log.jsonl              # R4 事件流
      timing.json            # R3 时间记录
      MANIFEST.sha256        # R5 完整性清单
```

证据包分级沿用五级：Installed / Configured / Connected / Called / VisuallyVerified，每级必须挂证据指针；低级不得推断高级。

## 7. 知识层检索接口（"统一检索"规格，v1 只接现成能力）

- 输入：需求卡 + 检索计划（类型化查询：参考站/组件/素材/契约知识）。
- 源：钉版语料 = 22 技能目录（含 uak-design-system 本地检索：79 风格/192 配色/74 字体对/119 UX 指南…）、source-catalog、designContracts（awesome-design-md 按需取用，不入库）。
- 输出：候选条目 `{type, source(repo+revision|URL), preview, licenseStatus, fitRationale}`；**许可过滤强制**，不可达源记 tried-degraded，绝不静默跳过。
- 每类候选上限（默认 ≤5），防信息过载。
- **非目标**：v1 不建爬虫、不上 embedding/RAG 索引——用现有本地检索+钉版目录；若 P1 访谈显示检索是主痛点，再在修订记录中升级。

## 8. 边界与非目标（诚实清单）

- 本规格不含任何实现；P3 前零代码。
- runner 不做质量判断、不做异常兜底决策（异常只记录）。
- 知识层是 C1 条件组件，**不是**研究贡献点；调度层机制是研究操纵对象，其"有效性"由实验检验，不在本规格预设。
- 现有 kit 的 showcase/evals/docs 一律不动；实验改动全部落在实验分支。

## 9. 与研究计划的指标映射

| 计划指标 | 来源模块 |
| --- | --- |
| 人工监督时间（§5 指标表） | R3（C1 自动；C0 录屏编码） |
| 返工量 | R2 门3 回退记录 + worktree-diff |
| 缺陷检出率 | 门3 决策记录 × 评分者普查比对 |
| 过程数据（门停留/勾选行为） | R4 事件流 |
| 数据冻结防篡改 | R5 + prevSha 链 |
