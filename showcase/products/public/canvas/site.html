是什么

一个 UI 专项的智能体工作流：你出需求，它走门径、留证据、给回执。它不替你决定品味，但让每个决定都有依据。

门径而非黑盒

六个确认停点，每一步你都知道 AI 看到了什么、依据什么决定。

证据而非说辞

六维实测回执（桌面/移动/键盘/对比度/降动效/控制台），未测维度记 — 不虚记。

监管而非生成

生成能力按契约外接；我们负责接入的验收、边界与留痕。

越用越懂你

品味档案只从你的原话与明确选择推导，可回溯、可删除。

怎么用

三步：装好、说需求、看证据。

安装

克隆仓库并跑通校验，确认环境可用。

git clone https://github.com/muzimu217/ui-design-agent-kit.git
cd ui-design-agent-kit && npm ci --ignore-scripts
npm run verify && npm test

说需求

在你的宿主（Codex / Claude Code / Cursor / Copilot 等 13 个）里用日常语言描述界面。工作流会先进入门 A 确认方向。

看证据

每个产物带六维实测；随时可重建工作台、跑验收、导出离线复核包。

npm run canvas:build   # 工作台（产物墙+对比）
npm run canvas:check   # 实测验收 + 三层守卫
npm run canvas:export  # 离线复核包（含 COMPARE.md）

六道门

门不是流程装饰：没有你的确认，工作流不会把"做完了"当成"做好了"。

  • A方向确认确认需求摘要与范围，避免做错方向
  • B参考素材确认参考来源（不抄外观，学机制）
  • C设计契约确认 DESIGN.md（颜色/字体/间距/动效参数）
  • D修订根据实测问题决定改什么
  • E验收看六维实测回执，决定是否通过
  • F留痕记录能力版本与证据路径，便于复现

能力接入

外部能力要进来必须回答四问：谁产出、边界在哪、如何验收、证据在哪。空槽位是诚实状态——没找到满足条件的候选就不接。

服务条款与边界

我们提供工作流与验证纪律，不提供模型服务、账户、生成引擎或第三方素材授权。完整条款见仓库 docs/terms.md。

我们保证

每个产物附实测回执；检视级别如实标注；未测维度不虚记；失败与降级如实记录。

我们不保证

设计一定"好看"；外部生成能力质量；跨环境一致性——发布前需在目标环境复验。

你的责任

方向确认、素材合规、凭据保管；上传内容须你有权使用。

数据与隐私

全部本地；无后端、无遥测；竞品截图仅内部研究，不外发；品味档案可删除。
