# 门A 方向稿：「山径」本地徒步旅行社 · 预订应用（direction-draft-gate，冲刺 6/8）

> 场景：本地旅行社的实质性新预订 Web 应用；无既有设计系统；用户尚未见过任何方向。
> 本稿为**环节 1 产物**：先于任何素材检索与代码。状态：**自动轮·待用户裁决**
> ——门A 通过前不进入环节 2（素材检索）与环节 6（代码），未代替用户过门。

## 0. 任务分类与边界

- 类型：实质性新 UI（预订流，桌面 + 移动响应式，无既有设计系统）。
- 内容现实：无真实 API 与真实档期——所有线路、价格、余位为**演示数据**，
  页面须常驻演示标注（延续 kit 诚实验收口径）。

## 1. 用户与主任务链

- 受众：25–55 岁周末徒步者；桌面比价与预约，移动端行前查看与改期。
- 主任务链：选线路 → 看档期/余位 → 选日期人数 → 联系人 → 确认预订。
- 次任务：我的预订查看/取消；按难度/时长/日期筛选。

## 2. 视觉基调（命名基线 + 检索边界披露）

- **基线方向**：「国家公园预约系统 × 现代预订台」——自然色系（苔绿 `#5a7d4a`
  级主色、岩灰墨字、米白底），大图线路卡，价格与余位状态一眼可辨。
- **命名基线**：Airbnb 式「列表/地图双轨预订」信息架构 + 国家公园预约系统的
  档期状态语义（可预约 / 少量余位 / 已满）。
- **检索边界披露（如实）**：本稿先于任何素材检索写成（场景要求方向先行）。
  上述基线是**方向性命名，未经本轮检视**——门A 通过后，环节 2 将以
  ui-ux-pro-max 检索 + 可检视来源核实后才可采纳，未核实前不作为实现依据。
- 字体：系统栈（kit 约束：无外部字体 CDN）。

## 3. 结构草案（四屏 + 全局）

1. **线路列表**：筛选（难度/时长/可约日期）；卡片 = 封面 16:10 + 名称 +
   距离/爬升/价格（等宽数字）+ 下期档期余位徽标。
2. **线路详情**：图集、行程亮点、装备清单、档期日历（余位状态格）、
   评价摘要、预订入口。
3. **预订流程**：三步 stepper（日期人数 → 联系人 → 确认）；价格随人数
   实时合计；每步可回退。
4. **我的预订**：状态列表（待确认/已确认/已完成）+ 取消入口（带确认对话）。
- 全局：顶栏（标识/搜索/我的预订）；移动端底部三 tab（探索/预订/我的）。

## 4. 动效意图（motion-contract 家族）

| 类型 | 意图 | 约束 |
| --- | --- | --- |
| 反馈 | 卡片 hover 抬升 1px + 描边高亮；按钮按压 | ≤150ms |
| 流转 | stepper 步进内容切换 shared-axis；日历月份切换同轴滑动 | 级联 40–60ms |
| 状态语义 | 余位数变化数字过渡；售罄置灰**无动画**（状态不靠动效渲染） | — |
| 降级 | `prefers-reduced-motion` 全部静态化 | 全局 |
| 工具链（预告，未实现） | motion/react（本地已有，MIT）；曲线以 Motion 文档检视记录为准 | 门F 届时留痕 |

## 5. 关键组件期望（组件/交互粒度）

- **档期日历**：日期格触达目标 ≥44×44px；余位角标 ≤3 显示具体数、0 显
  「已满」；禁用格不可聚焦；月份切换为按钮 + `aria-live` 播报（键盘可达）。
- **线路卡**：整卡可点、卡内唯一主操作；触达 ≥44px；封面 `alt` 必填。
- **stepper**：当前步 `aria-current="step"`；已完成步可点回退。
- **空态**：筛选无结果 → 图标 + 「清空筛选」真实按钮（不提供死胡同）。
- **价格合计**：人数变更即时更新，`aria-live="polite"`。
- 焦点环全局可见（2px，offset 2）；演示横幅常驻顶部。
