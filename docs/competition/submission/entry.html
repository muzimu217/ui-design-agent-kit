一句话定位 & 与评审维度的对应

现有 AI 界面工具都在比"生成得更快更多"，UI Design Agent Kit 解决的是没人管的那一段："生成之后，怎么证明它真的能用。"它是一层装进任意编码智能体的工作流指令：需求先对齐、素材有出处、改动有边界、验收有浏览器实测证据、交付可审计——每一步的关键决策都停下来等人确认。

三、技术创新（30%）①：行业谱系里的第四层

我们检索了 19 个同类产品（v0、Lovable、Bolt、Figma Make、Base44、Cursor、国产即时设计 / Pixso / MasterGo 等，检视记录全部开源在仓库 docs/competitive-insights/），它们可以排成一个谱系：

验证结构三件套（白话）

① 六道门
方向、素材、原型、契约、验收、留痕——每道门都是人工停点：AI 把方案摆上来，人来点头，不点头不动手。
② 五级证据
"装了 ≠ 配了 ≠ 连上了 ≠ 调通了 ≠ 页面验过了"。任何"完成"的声称，都要说清到第几级、证据在哪。
③ 改动半径
来自真实开发者问卷的三条血泪（重写整页 / 悄悄删边界代码 / 一次改 7 个文件）变成硬规则：动手前先声明改哪些文件，不重写、不换库、不删既有行为。

与"简单堆砌现成工具"的区别：本作品的核心资产是自研的工作流指令与验证体系（22 个技能、26 个知识参考、12+ 验收工具、131 项自研测试），现成工具（Playwright、Remotion 等）只作为被编排的执行件。

七、开源治理（20%）

协议与合规
Apache-2.0；第三方依赖与素材许可集中登记（THIRD_PARTY_NOTICES + 许可清单）；上游技能钉版锁定（tooling/sources.lock.json），宿主商标图标仅作兼容性说明。
贡献机制
单人维护 + 智能体协作流水线：所有改动走 dev/auto 分支 → 三连验证（安装 / 校验 / 131 测试）全绿 → PR 合并 main；绝不直推 main、绝不改写历史。
文档体系
README / 使用指南 / 架构说明 / 决策记录（ADR×4）/ 安全基线 / 迭代日志（每轮含验证结果）/ 竞品检视档案（19 轮全部开源）。
Issue / PR 纪律
GitHub PR 工作流已实际运行（本届参赛即含一次 25+ 提交的完整 PR 审阅链）；反馈模板与发布白名单机检在库。

八、长期发展（20%）①：这个仓库怎么被持续维护

双线自动化维护机制（已连续运行 5 周，全部留痕可审计）：仓库由"开发线 + 研究线"两条轮值线维护，每日交替各跑一轮——

轮值线每轮做什么产出留痕
开发线（偶数时）一轮市场对标学习（选品→浏览器实看取证→知识卡→落地优化）+ 工程任务；三连验证全绿才提交迭代日志 19 轮 + 竞品档案 19 份
研究线（奇数时）健康探测 / 语料整理 / 实验设计推进；重大方向必须预注册后执行研究轮次记录 19 份（独立私有仓）

研究路线（白话）

· 已经做完的：面向 GitHub 开源开发者发放需求问卷，共回收 28 份（首批 4 份已完成深度整理，痛点原话直接变成了产品的改动半径纪律，其余整理在录）；19 个同类产品的市场检视；一套预注册式实验设计（先写好评判标准再做实验，防止事后挑数据）。
· 正在做的：从 GitHub 议题、技术论坛等公开渠道持续收集真实用户痛点语料。
· 如实验证（如实）：门控工作流是否比裸用 AI 检出更多缺陷——受控对照实验尚未执行（设计已冻结，参与规模待定后启动）；本册所有质量数字均来自工程实测，不冒充用户研究结论。

十、诚实边界与开源声明

如实声明

· 问卷共回收 28 份（首批深度整理 4 份），为形成性证据、非统计样本；受控对照实验尚未执行，无因果结论。
· 截图证明对应页面某次检查结果，不代表所有任务均通过验收；触屏真机与读屏全链路未测项在各 README 标注。
· Kit 不提供模型服务、账户、付费素材或后台接口；宿主自备模型与工具连接。
· 案例数据均为虚构演示数据；竞品截图仅作内部研究证据（不上展厅不外发），本册仅使用第一方截图。
