## 四、门B 三问裁决

### Q1 — 字体：系统栈 vs. 引入 OFL 等宽 — **选 A（纯系统字体栈）**

理由：这个产品的数字是**读数**，不是品牌表达。系统栈的等宽字体（SF Mono / Consolas）在各自平台上都是原生优化过的，比引入 web 字体加载更快、许可负担为零。引入 JetBrains Mono 能提升"仪器面板"质感，但代价是字体文件 + OFL 声明义务，而收益在中文为主的页面上被稀释（中文仍需系统栈）。**第一版不引入。**

> 补充要求：数字必须用 `tabular-nums`（等宽数字特性），否则读数跳动时宽度会变。

### Q2 — 是否补 R3 的浏览器实地观察 — **要，必须补**

理由：子代理 A 诚实说明它只确认了 Tide Guide 的 HTTP 200 和标题，**没有亲眼看到曲线 UI**（站点是客户端渲染）。而 R3 恰恰是"曲线即 hero"这个核心判断的唯一同类证据。

> 裁决：**契约阶段用真实浏览器打开 tideguide.com，实际观察其曲线呈现并留痕**。如果打不开或看不到，就如实记录"未观察到"，并降级为描述级参考——不能拿"HTTP 200"当"我看过了"。

### Q3 — 曲线自绘 + 原生 range 作为时间轴 — **批准**

理由：自绘 SVG + 可聚焦的 `input[type=range]` 是正确的路径。用原生控件承载键盘交互，比自己实现键盘事件更可靠，也天然满足 A4（键盘可操作）。视觉上隐藏 range 但保留其可聚焦性，需要确保焦点环可见——这点在验证阶段会核对。

> 补充要求：隐藏视觉样式但**不得使用 `display:none` 或 `visibility:hidden`**（那会让控件失去可聚焦性）。用 `opacity:0` + 定位覆盖，或 `appearance:none` 保留在布局中。
