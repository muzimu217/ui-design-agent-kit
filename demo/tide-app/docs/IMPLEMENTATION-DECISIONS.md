## 逐条裁决

### 1. 基准面偏移（`DATUM_OFFSET_M`）— **批准**

**问题**：契约写 `h(t) = 1.15·sin(...) + 0.35·sin(...)`，单位"米，相对最低低潮面"。但纯正弦叠加会取负值，而"相对最低低潮面"按定义不为负——**契约的公式与文字自相矛盾**。

**裁决**：**批准加偏移**。实现取 `1.15 + 0.35 = 1.50`，使曲线全程 ≥0、最低点 0.09 m。这是对契约缺陷的正确修补。

**但要求补契约**：在 `DESIGN.md` 的公式处补一句说明偏移量的来源与含义，避免后人再困惑。

### 2. φ₁/φ₂ 未定稿 — **批准实现期的拟合值**

契约已授权实现期拟合。实现按契约示例（高潮 06:11 / 18:30 附近）拟合出高潮 06:10 / 18:30、低潮 12:20，合理。

**并且它做对了一件事**：契约"待定项 3"说赶海窗口由数据算出，实现照做（算出 10:20–12:20），**没有照抄契约示例里的 12:40–14:40**。这是正确理解——示例值属于另一组相位，照抄才是错的。

### 3. 契约 9.2 自相矛盾（PageUp 步长）— **批准覆写**

契约 9.2 说"PageUp/PageDown = ±6 步……全部为原生行为，不自行实现"，但原生 `input[type=range]` 的 PageUp 步长由浏览器决定，不保证 6 步。**契约的假设是错的。**

**裁决**：批准覆写这两个键，其余保留原生。

### 4. D1 与 9.5 冲突（chip 背景）— **维持 D1**

门D 裁决 D1 明确要求"不可点击的 chip 不得呈现按钮样式"。契约 9.5 说用 `--surface-3` 底。**门D 裁决优先**（它是后出且更具体的裁决）。

实现的处理更好：把标注移进曲线留白带，因此不需要底色衬底就能读，对比度反而更高（13.14:1 vs 契约估的 11.10:1）。

### 5. Do #3 与 9.6 冲突（场景卡图标用色）— **维持 Do #3**

Do #3 说强调色只用于三处。实现按 Do #3 用 `--text-primary`。这与门A「强调色只用在数据和当前时间上」的意图一致。

**批准**，并把 `::selection` 与品牌图标也一并收归中性色，使强调色严格只剩契约允许的用途。

### 6. `touch-action: none` 副作用 — **保留，但记录风险**

契约第 4 节把它列为允许写法，实现照写。副作用是 375px 下手指落在曲线上时页面不滚动。

**裁决**：保留（契约已决定），但在验收记录中登记为**已知风险**。理由：这是海钓用户戴手套时的真实场景，值得后续观察。

### 7. 9.5 窄视口降级与 Do #8 冲突 — **维持始终显示**

9.5 说窄视口"只保留潮位数值、时刻移入 aria-label"，Do #8 说"直接标注时刻与潮位"，9.5 自己又说"不隐藏信息"。三处冲突。

实现实测 375px 下"06:10 · 2.88 米"完全放得下（标注约 92px 宽，两个高潮标注在 25.7% 与 77%，不重叠）。

**裁决**：**维持始终显示**。既然放得下，隐藏信息反而违反 Do #8 与 9.5 自身的"不隐藏"原则。

### 8. `?state=loading` / `?state=empty` 验证入口 — **批准保留，但要求标注**

演示数据是同步生成的，没有真实异步源。为实现契约要求的加载/空态可被核对，它用 URL 参数打开真实代码路径，**没有引入假延时或伪 handler**。

**裁决**：**批准保留**。这是诚实做法——用真实代码路径而非伪造状态。但要求：
- 在 README 中说明这两个参数是**验证入口**，不是产品功能
- 不得在默认路径下出现加载态（默认路径直接给读数，满足 A2）

### 9. `--text-disabled` 的使用 — **批准**

只出现在已禁用控件上，未用于任何可读文本。加载/空态的占位读数用 `--text-secondary`（≥7:1），比走 WCAG 对 disabled 的例外更安全。
