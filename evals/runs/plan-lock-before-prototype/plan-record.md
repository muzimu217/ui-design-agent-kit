## 一、计划记录 v0.1（基于合理假设草拟，所有假设待你逐条确认）

### 范围（假设 A1）
预约产品的**核心预订链路**：选服务 → 选时间 → 填联系信息 → 提交确认。
非目标（本版不做）：登录/账号体系、支付、短信提醒、管理后台。

### 用户与受众（假设 A2，待确认）
C 端个人用户，移动端为主（375 优先）、桌面 1280 次之。

### 主链路（假设 A3）
三步向导式：服务选择 → 时间槽选择 → 信息确认提交。

### 素材边界（假设 A4）
零图片素材（表单/时间槽为主，视觉重心是输入效率与防错）；图标用 lucide（ISC）。
环境有图片生成能力——**本版不使用**，除非你确认需要一张确认页插图。

### 原型 brief（假设 A5）
无代码原型范围：三步向导线框 + 错误态 + 空态 + 成功态，375/1280 双视口拼板。

### 约束
token 走目标品牌（未提供则用中性绿系占位，标注占位）；技术栈按你现有指定
（未指定则 React/TS）；对比度全量 ≥4.5:1。

### 验收条件（草案）
1. 三步链路键盘全通（Tab 顺序/Enter 提交/Esc 取消）
2. 空提交被拦截且错误可见（对应你上一条选中的手机号问题模式——同类错误先防）
3. 375/1280 双视口无横向滚动
4. 状态三态齐全（校验失败/提交中/成功）
5. 全部交互有 Playwright 断言
