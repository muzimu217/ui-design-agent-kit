## 三、缺口分析（覆盖度 <80% 的排序）

### 缺口 1：大众化包装（影响 D1/D2，最高优先级）

UAK 用「评分台账+证据链+验收门」描述自己——对开发者精准但对大众晦涩。
B 站验证的需求表述是「拯救丑 UI」「提升 AI 审美」——**同一个能力，不同的壳**。

**所需动作**：写一份「大众化表述对照表」，把 UAK 每个功能翻译成 B 站受众的语言。
不改产品，只改对外文案。

### 缺口 2：横向对比数据（影响 D6/I3，差异化关键）

UAK 有 70 场景的评分数据，但没有其他工具的同口径数据。「我们 100 分」不如
「我们 vs 他们，同一道题，谁过谁不过」有说服力。

**所需动作**：选 2-3 个竞品工具（v0.dev / Cursor / Pencil），用 UAK 的 passCriteria
跑同样的场景，产出对比数据。需要开发时间。

### 缺口 3：可分发的内容形态（影响 D3/D5/I2，触达渠道）

54 个 run 目录有完整的证据链，但形态是「工程文档」不是「教程/视频」。需要把
现有素材转化为 B 站视频或图文教程。

**所需动作**：选一个最有代表性的 run（如 NODEGRID 或 data-dense），剪辑成教程
视频。需要剪辑工具和时间。

### 缺口 4：开箱即用的契约模板（影响 D7/I4，降低使用门槛）

design-contract.md 是指导性文档，用户需要自己填。B 站需求信号表明用户想要
「拿来就用」的模板。

**所需动作**：从 awesome-design-md + design-contract.md 提炼 3-5 个预填模板
（如「暗色 SaaS」「极简博客」「赛博游戏 UI」），发布为可下载资产。

## 四、开发路径（按缺口优先级排列）

### 近期（无需开发，纯文案/包装）
1. 写「大众化表述对照表」（缺口 1）
2. README 加「UI 工作流」关键词提升搜索发现性（缺口 1 延伸）

### 中期（1-2 个专注批次）
3. 从 awesome-design-md 提炼 3-5 个预填设计契约模板（缺口 4）
4. 选 1 个竞品工具 + UAK 的 passCriteria 跑对比（缺口 2）

### 远期（需要外部资源或用户决策）
5. 剪辑教程视频（缺口 3，需要视频剪辑工具）
6. 71 场景横评数据完善（缺口 2 延伸，需要竞品工具 API）

## 五、沉淀机制

本文件是「需求→能力→缺口→路径」循环的知识资产锚点。每次 B 站漫游/竞品
调研后：

1. **新需求信号** → 追加到 §一（带播放量/点赞量数据）
2. **能力覆盖变化** → 更新 §二（新功能上线或能力提升时）
3. **缺口变化** → 更新 §三（新缺口出现或旧缺口填平时）
4. **路径调整** → 更新 §四（优先级变化或新增路径时）

触发时机：B 站漫游发现新需求信号时 / UAK 新功能上线时 / 竞品有新动作时。
频率：每周至少一次，跟随晚间 B 站漫游轮。
