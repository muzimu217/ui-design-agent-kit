## §W 通道：网络公开证据采集规范（2026-10-02 开通）

> 背景：用户指令——"网上那么多证据那么多素材，偏偏要去问人？"；专人负责采集，落本项目目录用于完善研究。

**目录**：`research/formative/data/web/W-xx.md`（一事一案；批量采集按批次起 `W-01`…连续编号）。

**每案必填六项**（缺一不入库）：

```markdown
# W-xx ｜ <一句话主题>
- 平台/来源：Reddit r/webdev · HN · V2EX · 掘金 · X …
- URL：原始链接
- 采集日期 + 发言日期：
- 作者标识：匿名化（如 "reddit-user-A1"，不存实名/头像/主页链接）
- **公开摘录**（原语言逐字，可附中译并标"译文"）：
- 初步标签：FM-xx 候选 / 任务卡 T-x 相关 / 仅背景
```

**质量分层**：
- **A 级**：第一手经历贴（"我用 Cursor 做了 X，结果 Y"）——可编码；
- **B 级**：观点/讨论贴（"大家都遇到 Z 吗"）——只作背景佐证，不计人数频次；
- **剔除**：营销内容、软文、AI 生成的 SEO 垃圾、无具体经历的纯情绪宣泄。

**编码口径**：W 证据可与 Q/E 语料合并看模式**趋势**，但在任何计数表里**单列 W 行**，不与 5 人独立样本混算（公开样本无抽样控制，只做三角验证）。

## 目录结构

**看稿只去 `answers/`（Q 与 E 并置，一个目录看全）；原始件一律在 `survey-<id>/raw/`。**

```text
research/formative/data/
├── README.md                       # 本文件：存储规范
├── pull-survey-answers.py          # 问卷增量拉取脚本（新稿直接写进 answers/）
├── answers/                        # ← 统一阅览区（用户查阅入口）
│   ├── Q-01.md                     # 问卷回收 第 1 份
│   ├── Q-02.md                     # 问卷回收 第 2 份
│   ├── E-01.md                     # 外部书面表格（角色「独立全栈工程师」）
│   ├── E-02.md                     # 外部书面表格（角色「非技术产品经理 / Solo Maker」）
│   ├── E-03.md                     # 外部书面表格（角色「UI/UX 设计师」）
│   └── _cross-role-summary.md      # 整理者综合表，**非答者原话**
└── survey-<survey_id>/
    ├── manifest.json               # 拉取记录 + 已落盘索引（answer_id ↔ 本地编号）
    └── raw/
        ├── survey-<survey_id>.json # 问卷结构快照（题干可能被改，须留档）
        └── answer-<answer_id>.json # 单条回答原始 JSON，verbatim，一字不改
```

> `answers/*.md` 是可读渲染件；正文一律以 `raw/` 的原始 JSON 为准。`E-0x.md` 无对应 raw（原件未提供）。

## 拉取方式（腾讯问卷 CLI，本机无原生 MCP 工具）

```bash
mcporter call tencent-survey.list_answers --args '{"survey_id": 28072993, "per_page": 100}'
mcporter call tencent-survey.get_survey   --args '{"survey_id": 28072993}'
```

- 翻页：`list` 长度等于 `per_page` 时，用 `last_answer_id` 继续取，直到取完。
- 增量判据：按 `answer_id` 去重，只落盘新出现的 id，不重写旧文件。
- **可用性只认 `get_survey.state`**（2=发布/可回收，3=未发布）。**禁止用 `curl` 判断**——投放页是 React 外壳，发布与否都返回 200。
