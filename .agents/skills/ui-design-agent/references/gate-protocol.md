# Gate Protocol

> 门径与下一步审核协议。建立依据：2026-09-20 用户裁决——评测/夹具产物绕过门径
> 暴露指令层漏洞；"用户通过才能进行下一步指令"；"更擅长是抄而不是去模仿"。
> 本文件是门径的**机械执行契约**：SKILL.md 在任何会产生可视化产物的任务上
> 都必须走本协议。协议规则与 SKILL.md 冲突时，以更严格者为准。

## 1. 适用范围（先读，反豁免条款）

只要产物**会被渲染成视觉**——页面、组件、demo、夹具（fixture）、评测样本
（eval execution）、文档插图、图标、示意图、原型图——就是 UI 工作，一律走
本协议的门径。

- **不存在**"夹具豁免"、"demo 豁免"、"评测豁免"、"一次性产物豁免"、
  "内部工具豁免"。评测场景的执行本身就是对链路纪律的检验：绕门执行等于
  场景失败。
- 分级（S/M/L）只缩放**产物深度**（一份简短方向稿也是方向稿），永远不缩
  减**用户裁决**。分级由用户逐页确认（门账本 D3），不是代理自分类的通行证。
- S 档"窄修复"仅指：在**已有已批准设计**内修缺陷，不产生任何新的视觉决策
  （不改布局、方向、素材、风格）。只要出现新的视觉决策，门径自动重启。
- 代理不确定某产物是否触发门径时，**必须问用户**，不得自行判定豁免。

## 2. 抄 proven，而不是模仿（素材总则）

用户裁定原文：**"更擅长是抄而不是去模仿。"**

- 每个新视觉面（页面/组件/素材），第一步是找到**已被验证的成品实现**
  （上线网站、开源组件、授权素材），指定 URL，**贴着抄**：布局关系、交互
  模式、参数直接复用，注明复制了什么、授权边界是什么。
- "模仿"（看一眼风格后自己凭理解重画/重写）不满足本条。没有 named source
  的视觉产出是流程缺陷。
- **自绘素材（手绘 SVG/CSS 画图）默认禁止**，只有同时满足以下两条才允许：
  1. 书面记录"为什么找不到可拼接的现成素材"（检索了哪里、为什么不适用）；
  2. 用户在门B 明示批准该自绘。
- 实在找不到可抄的 proven 案例：声明检索过哪里、为何不适用，请用户批准
  "原创"这个例外。禁止静默原创。

## 3. 门径序列（每道门的契约）

每一道门 = **进入条件 + 必交产物 + 呈交格式 + 有效裁决**。产物深度按分级
缩放，裁决不可跳过。门A-E 是**用户裁决门**（停止点）；门F 是**留痕门**
（非用户停止点）。"六道门"（A-F）的计数含 F。

### 门A · 方向稿
- 进入条件：需求已整理（口语摄取或既有简报）。
- 必交产物：方向稿——**named proven baseline**（真实成品 URL + 打算抄哪些
  关系）+ 结构草图 + 动效意图 + **三旋钮值**（DESIGN_VARIANCE /
  MOTION_INTENSITY / VISUAL_DENSITY，各 1-10，场景推断表见 plan-execute.md
  "方向三旋钮"节；缺旋钮即为不完整呈交）；对照品味档案声明
  honoring/violating 条目。未实机检视的 baseline 必须标 `unverified`，
  过门后第一步就是实机校验。
- 基线查找与素材采挖的边界（R110-02）：为命名 baseline 所需的**最小定向
  检索**（少量已知来源，回答"真实成品是什么、长什么样"）允许在门A 前进行，
  不构成跳门或"重首轮"；**素材采挖**（多路候选搜集、截图对比、拟采用与
  改编提案）只属于门B。两种读法打架时：门A 只需要**一个**可指认的真实
  成品，不需要候选池。
- 呈交格式：短稿 + 一句话"下一步：等你裁决方向"。
- 有效裁决：通过 / 调整（附改法）/ 否（换向）。**裁决前不产出任何目标视觉
  产物**（包括草图、原型图、代码、素材采集成品）。

### 门B · 素材清单
- 进入条件：门A 通过。
- 必交产物：候选清单——真实来源（URL/本地路径 + 截图或检视记录）、拟采用
  部分、授权状态、改编边界。排序规则（R104-05）："可拉取组件 > 可检视
  源码 > 纯截图"是**类别桶优先级**；桶内按 material-scouting.md 的加权分
  排序，两套互不替代。
- 呈交格式：清单 + 用户选择请求。**用户选定前不写实现代码、不下载未批准
  资产。** 自绘例外（第 2 节）在此门申请。
- 有效裁决：用户选定（/ 调整候选 / 否，换向重找）。

### 门C · 原型（实质性新 UI 强制）
- 进入条件：门B 选定。
- 必交产物：来自所选素材的无代码原型（生成图或素材蒙太奇），或记录不可用
  与降级路径。
- 呈交格式：原型 + 接受/修改/拒绝三选一。
- 有效裁决：接受 / 修改（附改法）/ 拒绝（换向）。

### 门D · 契约（大项目/动效复杂强制）
- 进入条件：门C 通过，且任务为 L 级，或含超出既有动效预算的新动效面
  （新动效类别，或时长/复杂度超出 motion-contract 预设档）；判据拿不准时
  问用户，不自行降级跳过。
- 必交产物：DESIGN.md（Mission、语义 token、Do/Don't、动效参数、验收门）。
- 呈交格式：DESIGN.md 摘要 + 一句话"下一步：等你裁决契约"。
- 有效裁决：通过 / 调整（附改法）/ 否。**裁决前不进入实现。**

### 实现
- 进入条件：以上适用门全部 `passed`，且计划为 locked 状态（plan-execute.md）。

### 门F · 调用留痕（留痕门，非用户停止点）
- 定性：门F 是**留痕要求**，不是用户裁决门——它不呈交、不等待裁决；
  "六道门"计数含 F，但停止点只有 A-E 五道。
- 必交产物：实现中每 phase 的 MCP 调用痕迹（服务器 / 工具 / 实参与结果）
  随做随记，汇入验收记录。

### 门E · 验收（代码后每轮）
- 进入条件：实现产出可运行界面，或一轮修复完成。
- 必交产物：逐页问题清单（P0/P1/P2 + 证据）+ 替换建议；未修 P0 阻止验收。
- 呈交格式：清单 + 逐条处置建议，结尾"下一步：等你勾选修复项并确认验收"。
- 有效裁决：逐轮循环到用户明确确认为止；"生成完成"不等于"验收通过"。

## 4. 停点规则（"用户通过才能进行下一步"）

1. **一门一呈交**：一次呈交只对应一道门。禁止把方向+素材+实现打包呈交，
   禁止在等待裁决期间开始下一阶段的任何产出。
2. **呈交必带下一步**：每道门的呈交以固定格式结尾——
   `下一步：〈唯一动作〉——等你〈具体裁决问题〉。`让用户只需回答"过/改"。
3. **沉默不是批准**；"看起来不错"不是裁决；旧批准不覆盖新范围。
4. **裁决只覆盖它所回应的门**。"风格可以"≠门B 素材选定；"继续"≠门E 验收。
5. 裁决后进入下一步前，复述该裁决一行（留痕），再开始。
6. 状态机与措辞遵循 plan-execute.md；门上待决事项登记 docs/gates.md 账本；
   阶段状态用 tooling/workflow-stages.json 枚举。账本与枚举文件永远在
   **kit 仓库本体**，目标项目内不创建它们。
7. **用户可显式弃权某道门**（例如"别问了直接写"）——这是用户的权利，且必须
   留痕：哪道门、用户原话、时间，记入账本。**弃权只能由用户发起**：agent
   不得建议弃权、不得把沉默或催促当弃权；未留痕的"直接写"不构成弃权，
   仍按违规处理。弃权仅限当次任务范围，不延续到新范围。

## 5. 违规即 P0

产出任何可视化产物而**无法引用对应的门裁决记录**（哪条消息、哪个门、何时），
即为流程 P0：无论产物质量如何，阻止实现验收，必须回退到最近的未过门重走。
自查问句（写任何 UI 文件前）：

> 我能指出门A 的方向稿与用户裁决吗？门B 的选定记录呢？这个产物落在哪个
> 已授权阶段里？

答不上来 = 停下，先补门。

## 6. 评测场景的特别条款

评测场景（evals/scenarios.json）的执行**就是**链路执行：场景产物按本协议
走门（产物深度按 S/M/L 缩放）。场景台账记录门径痕迹（哪个门、呈交物、裁决
或"自动轮·待用户裁决"标注）。台账里没有门径痕迹的 UI 产物按第 5 节记 P0。
