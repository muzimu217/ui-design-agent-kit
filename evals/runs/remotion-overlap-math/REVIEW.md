# Timeline 时长评审（30fps，只读）

> 结论：**258 帧 = 8.6 秒**。未改任何文件，未发起渲染。

## 计算

三段场景 90 / 120 / 90 帧，场景时间总和 300 帧。两个内部转场分别重叠 18 帧和
24 帧，重叠意味着"后一段提前开工"，所以从总和中各减一次：

```
300 − 18 − 24 = 258 帧
258 ÷ 30fps = 8.6 秒
```

常见错法对照：直接相加得 300（忽略重叠）；每处重叠减两次得 216（把重叠当成了
删除而不是交叠）。本时间线无外侧转场、无 `Sequence` 偏移，不存在第三次扣减。

## 转场长度 vs 相邻场景

- 转场 1（18 帧）夹在 90 / 120 帧两段之间：18 ≤ 90 且 18 ≤ 120 ✓
- 转场 2（24 帧）夹在 120 / 90 帧两段之间：24 ≤ 120 且 24 ≤ 90 ✓

两处转场均短于任一相邻场景，不会出现"转场比场景还长"的负时长或空档。

## 叠加层（overlay）口径

如果之后加 overlay 类型的转场（上层交叉淡化，两段场景各自完整播放），
**时长不减**：overlay 不吃场景时间，总长仍是各段之和减去"真重叠"（crossfade
里前段提前结束的那种）。判定依据是转场的实现方式：子序列负偏移 = 减时间；
纯叠加 = 不减。本时间线的 18/24 按题意是重叠（overlap），按减法计。

## Remotion 帧时钟 vs Web 动效约束

Web 端"禁用恒速线性运动"是浏览器 UI 反馈的规约；Remotion 的帧时序是
确定性渲染时钟，每个时间点对应唯一输出帧，不受该规约约束。本评审不把
Web 动效契约套用到 Remotion 时间线上。

## 只读声明

本评审未修改任何工程文件、未调用渲染器、未启动 Studio。
