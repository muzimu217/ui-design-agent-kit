# 自学机制（Self-Learning Loop）

- 日期：2026-10-19 ｜ 依据：用户指令——"我们再通过自学与机制，每次更新、接纳更好的一些素材知识库，打造更好的知识库内容进行升级兼兼容……B站、哔哩哔哩或 YouTube 上有非常非常火的一些新项目、新产品，关于一些视觉系设计之类的，都要进行视频阅读和学习。高质量的、高播放量的，**每天都要按 KPI 这样做**。"
- 与既有 learn-loop 的关系：`docs/learn-loop.md` 是**产品对标**循环（机制层，对象=同类产品）；本文是**知识摄取**循环（内容层，对象=高播放视觉系内容）。两者每日并行，互不替代。

## 一、每日 KPI（缺一即当日不合格）

| # | KPI | 判定口径 | 落点 |
| --- | --- | --- | --- |
| **L1** | **视频学习 ≥1 条** | 当日实看至少 1 条高播放（≥10 万）视觉系内容，**按播放量排序取证**，记录标题/UP/播放/链接 | `docs/competitive-insights/<date>-<topic>/insight.md` |
| **L2** | **知识卡入库 ≥1 张** | 从 L1 提炼**可编码的机制**（不是观后感），写入知识库卡片 | `docs/knowledge-base/cards/<id>.md` |
| **L3** | **兼容性检查** | 新卡必须声明与既有卡片的关系：`extends` / `supersedes` / `conflicts`（冲突时写消解结论） | 卡片 frontmatter `relations` |
| **L4** | **可执行转化 ≥0.5/日** | 每 2 日至少 1 条知识卡转成代码/规则/语料（不足则写暂缓理由） | iteration-log 记录 |

**质量闸**：只收录**机制级**知识（可复现、可编码、有适用边界）。纯审美偏好、无原理的口播、"看看这个炫酷效果"不收录。

## 二、每日流程（30-45 分钟）

1. **取料**：B 站/YouTube 按播放量排序搜索当日主题（轮换：动效 / 版式 / 色彩 / 3D / 视频叙事 / 交互 / 图标系统）；
2. **实看**：至少 1 条完整页实看（标题、UP、播放、简介、章节），截图存证（ADR-0002 本地留存）；
3. **提炼**：写出**机制命名**（一句话）+ 生效原因 + 可编码参数 + 适用边界 + 反例；
4. **入库**：按 `docs/knowledge-base/schema.md` 写卡片；
5. **兼容**：与既有卡比对，声明 extends/supersedes/conflicts；
6. **转化**：判断能否落成代码/规则/语料，能则立增量任务，不能则写暂缓理由。

## 三、知识库升级与兼容规则（本轮重点）

### 3.1 版本与兼容

- 知识库有 **schema 版本**（`docs/knowledge-base/schema.md` 头部 `schemaVersion`）；卡片有 **card 版本**。
- **向后兼容优先**：新增字段必须有默认值；删除字段必须先标 `deprecated` 一个周期。
- 破坏性变更（改名/改语义）必须写 **migration**：`docs/knowledge-base/migrations/NNNN-<name>.md`，含旧→新映射与受影响卡片清单。
- 卡片**不删除**，只 `status: superseded` 并指向新卡——**知识演进要留痕**（与产物墙 append-only 同纪律）。

### 3.2 冲突消解（L3）

当新知识与旧卡冲突：
1. 先判定是**真冲突**（同一条件下结论相反）还是**边界不同**（适用场景不同）；
2. 边界不同 → 新卡写 `scope`，两卡并存；
3. 真冲突 → 以**可复核证据**强者胜；证据不足则两卡并存并标 `conflicts`，等待更多证据（**不拍脑袋裁决**）；
4. 消解结论写入新卡的 `resolution` 字段与当日 iteration-log。

### 3.3 素材知识库接入（与 capability-adapters 的关系）

- **外部知识库/素材源**（如 Mobbin MCP、设计系统库）按 `docs/capability-adapters.md` 四问登记；未通过四问的**不得作为交付依据**，但可作人工参考并留 `rejected` 记录。
- 视频/文章等**内容素材**属"参考素材"，按门 B 规则记录来源与检视级别（`unverified-partial` 起步），**不得直接作为设计契约**。

## 四、每日记录格式（iteration-log 追加一行）

```
| <日期> | 自学 L1-L4 | 视频：<标题>（UP，播放，链接）→ 机制命名：<一句话> → 卡片 <id>（relations: extends/supersedes/conflicts）→ 转化：<增量/语料/暂缓理由> | 截图路径；卡片路径 | 下轮主题 |
```

## 五、反自欺条款

- 播放量只作**热度信号**，不作质量判据（与产物墙"来源≠质量"一致）；
- 未看完不得写"已学习"；只看了标题必须标 `title-only`；
- 不得把"看了一个教程"当成"掌握了机制"——卡片必须给出可编码参数，否则标 `incomplete`；
- 知识库条目数**不是 KPI**，可执行转化才是。

## 六、与其他机制的边界

| 机制 | 对象 | 频率 | 产出 |
| --- | --- | --- | --- |
| learn-loop（产品对标） | 同类产品/竞品 | 每开发轮 | insight + KPI4 对比 |
| **self-learning-loop（本文）** | 高播放视觉系内容 | **每日** | 知识卡 + 转化 |
| capability-adapters | 外部生成能力 | 按需 | 接入登记 |
| evals 语料 | 可测行为约束 | 每开发轮 +2 | 场景卡 |
