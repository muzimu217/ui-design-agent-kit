## 二、开发提示词（编译稿 · 可直接交给联网 AI）

> **目标**：内部采购申请工具 v1（桌面端）——采购申请列表、状态筛选、行详情查看。
>
> **范围**：v1 只做桌面端三件套；**移动端范围待确认**（不在本轮约束内）。
> **技术约束（已确认，不得迁移）**：沿用现有 Vue 3 栈与既有组件；图片用用户自有素材
> （授权证据在 P-7 记录）；不引入未选组件。
> **页面与流程**：①列表页：申请单号/标题/状态/金额/申请人/日期 六列，状态筛选
> （全部/待审批/已批准/已驳回——**枚举终版待确认**）；②行点击展开或侧栏详情：
> 申请人、事由、明细行、时间线。
> **状态与数据**：演示数据显式标注 demo data；**真实 API 接入待确认**——当前所有数据
> 走本地 mock，不得假装已对接审批系统。
> **权限**：审批权限模型**待确认**——界面只做状态展示与筛选，不做审批操作入口，
> 不得把「待审批」实现成可点击的审批动作。
> **素材映射**：列表行卡与筛选分段控件映射 inventory-console 已验证模式；详情
> 抽屉映射 P-7 已确认结构；自有图片用于空态与详情头部。
> **可观察验收方法**：筛选切换 ≤150ms 反馈；状态色对比 ≥4.5:1；详情键盘可达
> （Tab 进入/Esc 关闭/焦点归还）；空态/加载态/错误态齐备；1280px 与 375px 无溢出；
> console 0 错误。
>
> **目标环境声明**：执行前必须先检查你环境里的真实工具与文件可用性；本提示词中
> 标注「待确认」的三项（API/权限/移动端）在用户书面确认前保持未实现。
> **停止点**：交付可运行页面后停在验收环节，等待用户逐项勾选；本提示词不构成
> 任何后续阶段的自动授权。
