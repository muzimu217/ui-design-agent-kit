# 能力接入契约（Capability Adapters）

- 日期：2026-10-19 ｜ 依据：用户定位裁定——"我们主打的是工作流……相关知识库和 AI 功能让它进行接入就行了……专注工作流的监管和产品质量把控"（docs/identity-and-direction.md v4）
- 一句话：**本仓不重造生成能力；任何外部能力进入工作流，必须按本契约登记、按本契约验收、按本契约留证。**

## 一、为什么需要契约

市面生成能力（图像、3D、视频、模型）迭代快于工作流。若把生成能力内建，工作流会被拖入军备竞赛（妙多 Motiff 死亡复盘的教训之一）。**外接 + 监管**让工作流保持稳定，而生成能力可随时替换为当时更强的那个。

代价是：外部能力的质量不由我们控制。**契约的作用就是把"不可控"变成"可验收"**。

## 二、接入四问（缺一不得接入）

每个外接能力必须回答：

| # | 问题 | 记录位置 |
| --- | --- | --- |
| 1 | **谁产出**：能力名、提供方、版本/钉版（commit/tag/模型 ID） | 登记表 `capability` 行 |
| 2 | **边界在哪**：能做什么；**明确不能做什么**（防止越界使用产生静默错误） | 登记表 `limits` |
| 3 | **如何验收**：该能力专属的验收口径（**不得套用网页六维**） | 登记表 `acceptance` |
| 4 | **证据落在哪**：产物路径 + 回执文件 + 检视级别 | 登记表 `evidence` |

## 三、验收口径分类（按产物类型，不按工具品牌）

| 产物类型 | 验收维度 | 说明 |
| --- | --- | --- |
| 网页/界面 | 桌面/移动/键盘/对比度/降动效/console（六维） | 既有口径 |
| 静态图像 | 尺寸/格式/色域/来源血缘/生成参数可复现 | 新增：需记录 prompt 与 seed 等可复现参数 |
| 3D 资产 | 面数/包围盒/材质完整性/加载性能 | 新增：需在浏览器中实测加载 |
| 视频 | 时长/帧率/确定性（同输入同输出）/音画同步 | 新增：确定性=帧可复现，见 hyperframes 学习结论 |
| 代码/配置 | 可运行/测试通过/无越权访问 | 沿用三连绿 |

**跨族原则**（源自 KPI4 边界条件，增量 28）：不可观测维度记 **0/0 不适用**，不得记 0 分，也不得省略对比。

## 四、登记表（机器可读，工作台直接渲染）

权威数据：`canvas/capabilities.json`。工作台入口页"能力接入"区块由它渲染。

字段：

```json
{
  "id": "image-gen-xxx",
  "name": "示例图像生成能力",
  "provider": "外部提供方",
  "pinned": "版本/commit/模型ID",
  "status": "adopted | evaluating | rejected",
  "limits": "明确不能做什么",
  "acceptance": "该能力专属验收口径",
  "evidence": "产物与回执路径",
  "inspectionLevel": "verified | unverified-partial",
  "note": "接入判读"
}
```

## 五、状态机

- `evaluating`：已实看/试跑，未完成验收 → 不得用于交付产物；
- `adopted`：四问齐备 + 验收口径实测通过 → 可用于交付，证据入产物墙；
- `rejected`：不满足边界/许可证/质量 → 记录理由，防止反复重评。

**降级规则**：已 adopted 的能力若上游破坏性变更，状态退回 `evaluating` 并如实记录（不静默继续使用）。

## 七、与门径的关系

- **门 A**：确认需求时，若需要外接能力，必须写明能力与边界（不得笼统说"用 AI 生成"）；
- **门 B**：参考素材可来自外部知识库，需记录来源与检视级别；
- **门 D**：修订时若替换能力，需重跑该能力专属验收；
- **门 E**：验收按第三节口径分类执行，**不接受"工具说它行"作为证据**；
- **门 F**：留痕包含能力名+版本，便于复现。

## 八、不做什么（自我约束）

- 不因市面出现更强能力就扩张本仓生成栈；
- 不接入无法钉版或无法本地复现的能力用于交付；
- 不用外部能力的宣传口径替代实测；
- 不在本仓内实现模型推理服务。
