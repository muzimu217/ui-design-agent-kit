# 北极星目标与迭代机制（Goal & Iteration Loop）

> 交付对象：维护本 kit 的工程师与自动迭代任务。本文档回答三个问题：
> 这个项目「做到最好」长什么样（目标）、每一次完善怎么走（五步循环）、
> 如何不断线地走下去（定时任务与自更新边界）。
> 建立于 2026-09-06，基线见第四节，修订记录见第七节。

## 一、北极星

**把 UI Design Agent Kit 打磨成可复现、可评分、可持续的自我进化设计智能体系统：**

- **可复现（Replay）**：任一历史产出都有完整留痕，能按记录重放并对比；
- **可评分（Score）**：每次 kit 改动有前后分数对比，分数不降才合入；
- **可持续（Schedule）**：迭代、巡检、上游探测由定时任务持续执行，人只在门上裁决。

现有基础：思维链已到 v7.1（Plan/Execute 双模式 + 六阶段思维内核 + 六道
确认门 + 门F MCP 门禁 + 细节级自我批评内环 + 门账本 + 任务分级），
机械层校验齐备。缺口正是上面三条——评测场景（现 36 个，2026-09-07
口径）大部分仍是静态规范而未真实跑分（6 个已有真实分数），demo 有验收
记录但无重放规范，迭代冲刺机制已随本文档启动、月度巡检仍未建。

## 二、「做到最好」的可验证定义

以下五条全部满足即达标，作为长期退出条件：

| # | 标准 | 证据 |
| --- | --- | --- |
| 1 | 任意产出：验收记录六门 + 内环 + 门F 痕迹齐全，无隐藏未修 P0 | ACCEPTANCE.md 覆盖率 100% |
| 2 | 任意 kit 改动：附改动前后评测分数对比，分数不降才合入 | iteration-log 每条含分数 |
| 3 | 任意中断：从 iteration-log + git 历史可无上下文恢复继续 | 冷启动恢复演练通过 |

| 5 | 合规底线：锁定率 100%、verify 0 错误、无内联密钥 | npm run verify 持续通过 |

## 三、阶段目标

### G1 评分闭环（2026-09 内出基线）

把 `evals/scenarios.json` 从「静态行为规范」升级为「可执行评测」：

- 新建 `scripts/eval-run.mjs`：按轮转从 29 个场景抽样真实执行（每轮冲刺
  1-2 个，一季度覆盖一轮），产出结构化结果（场景 id / 逐条 passCriteria
  判定 / 分数 / 证据路径）；
- 评分口径：每条 passCriteria 0-2 分（0 未做 / 1 做了但不完整 / 2 有证据
  地做到），failConditions 命中任一条该场景记 0 分；
- 在 `docs/iteration-log.md` 记录 v6 基线分，此后每次 kit 改动附前后对比；
- 验收：≥3 个场景有真实执行分数，且「改动 → 分数」对比链条成立过一次。

### G2 复现闭环（2026-10 内）

- 定义「重放包」规范（`docs/replay.md`）：需求输入 + 门A 方向稿 + 素材
  选择 + 契约 + 实现 + 证据 + 验收记录；以 `demo/blog-demo` 为样本补齐；
- 任一历史 demo 按重放包可重建，重建产物与原版做分区截图对照；
- 验收：blog-demo 重放包完整且重放对照留痕。

### G3 持续化（已随本文档启动）

- **迭代冲刺**（定时任务）：2026-09-06 起进入**8 小时冲刺模式**——每小时
  一轮、全天共 8 轮（第 1 轮由主会话执行，后续 7 轮每小时 :15 自动触发，
  当日约 16:15 收官）；冲刺结束后恢复每周节奏（待用户确认）；
- **每月 1 日 10:00 新鲜度巡检**（**待创建**：每会话限建一个定时任务，
  需在新会话中按本节与 quality-monitor 第四节月度清单创建；创建前该清单
  由人工按月执行）；
- 自更新边界（硬性）：上游差异**只报告不自动升级**；定时任务**不 push、
  不代替用户过确认门、不改 `tooling/sources.lock.json` 锁定 revision、
  不启用或认证任何可选 MCP 服务、不把密钥写进文件**。

## 五、五步迭代循环（每一次完善的固定动作）

1. **取目标**：读 iteration-log 上一轮「下一步」，或按轮转取下一个未评分场景；
2. **复现基线**：机械层三连（`npm run verify` / `npm test` /
   `npm run prompt:build`）+ 复验上一轮关键证据仍然成立；
3. **实践**：按 v6 思维链真实执行本轮选定场景或 demo 增量，六门留痕；
   自动轮产物停在用户门前（标记「自动轮·待用户裁决」），**不得代替用户
   过确认门**；
4. **评估与改进**：按 rubric 打分并与上一轮对比；只做**一处**最小改动，
   且必须落在组件/交互细节粒度（用户的质量标准：粗粒度的新流程环节不算
   改进，逐细节的评估维度、严重度分诊、未修复留痕、呈现前自我批评这类
   「内环」才算）；改完机械层三连确认不回退，无需改动则如实记录；
5. **留痕**：iteration-log 追加条目（日期 / 做了什么 / 分数或证据 / 下一步）
   + 中文提交信息 git commit（风格同仓库历史），不 push。

## 六、持续化机制与责任分工

| 任务 | 频率 | 执行者 | 产出 | 边界 |
| --- | --- | --- | --- | --- |
| 迭代冲刺 | 每周一 09:00 | 定时任务 | iteration-log 条目 + commit | 不 push、不过用户门、单变量改动 |
| 新鲜度巡检 | 每月 1 日 10:00 | 定时任务 | 可达性表更新 + 上游差异报告 | 只报告不升级 |
| 机械层三连 | 每次改动后 | 冲刺 / 人工 | verify/test/prompt:build 结果 | 已存在，不新增 |
| 用户门裁决 | 交互会话 | 用户 | 门A-E 签字 | 定时任务不得代替 |
| 目标修订 | 随目标变化 | 用户 + 主代理 | 本文档第七节追加记录 | — |
